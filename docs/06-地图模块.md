# 06 · 地图模块（Map）设计规范

> 状态：v0.1.0（2026-11-16）· 对应 `CONTRACT_VERSION 3.0.0`（本模块不新增 op、不改引擎契约）
> 目标：给场景（`loc`）和 NPC 一个坐标；玩家可以通过地图选点切换场景；场景带描述与链接（玩法 / 固定 NPC / 对话）；玩家可以在地图边缘创造新场景（管理员审核 → AI 生成 → 再审核 → 实装）；NPC 按日程自行移动。
> 本文件是地图模块的**接口契约**；凡涉及全局名字，仍以 `03-接口总表.md` 为准。本模块**不新增 op 原语**，全部行为由 13 个原语组合。

---

## 1. 边界与不变量

| 事项 | 做法 |
|---|---|
| 世界状态 | 场景/NPC/玩家位置全部落 `WorldState`（`loc` 实体 + `located_in` 边 + `scene`）；地图数据文件只是**内容模板** |
| 写状态 | 只有 `Arbiter.apply`；模块只产 `Proposal`，服务端只组装 `Proposal[]` |
| 引擎 / canon | **不改** `packages/engine/**`、`content/canon/**` |
| 玩家新场景 | 一律 `origin:"ai"`, `canon:false`，经两次管理员审核后才 `entity.create` 进地图 |
| 坐标 | 复用属性注册表 `coord_x` / `coord_y`（`number`，scope `loc/npc/plr`），不硬编码 |
| 时间 | 不新增时间原语；NPC 日程由 `map` 模块的 `tick` 在 `clock.advanced` 语义下移动 |

## 2. 内容数据（只读模板）

### 2.1 `content/modules/map/data/world_map.json`

```jsonc
{
  "schemaVersion": 2,
  "worldId": "ecust_campus",
  "width": 6000, "height": 4500,
  "image": "/map/ecust-campus.jpg",
  "startLocId": "loc_library",
  "scenes": [{
    "id": "loc_library", "name": "图文信息中心",
    "x": 3220, "y": 2320,
    "status": "built",              // built | under_construction | planned
    "category": "study",           // teaching/lab/dorm/food/sports/gate/landmark/life/study/admin/other
    "desc": "……场景描述，进叙事用……",
    "tags": ["安静", "线索"],
    "links": [
      { "kind": "module",   "id": "trade",               "label": "馆内小卖部" },
      { "kind": "npc",      "id": "npc_lin",             "label": "林静（流通台）" },
      { "kind": "dialogue", "id": "dlg_library_stacks",  "label": "问问过刊室" }
    ],
    "dialogues": [{
      "id": "dlg_library_stacks", "npcId": "npc_lin", "title": "问问过刊室",
      "lines": ["林静把借阅章按回印泥里……", "……", "……"]
    }]
  }]
}
```

- `width/height` 是底图原始像素尺寸；`x/y` 是同一坐标系里的点位。`image` 是 `apps/web/public/` 下的路径（当前 `/map/ecust-campus.jpg`），前端按 `document.baseURI` 解析后再铺满画布，缺失时退回纯色底。
- 底图由用户提供（`mmexport1794882591567.jpg` 转码为 6000×4500 JPEG），**来源/授权未确认**；公开部署或再分发前请确认授权，或替换为有授权底图。
- `status`：`built` 可进入；`under_construction` / `planned` 只展示（前端只选中并在详情提示，不调 `travel`；服务端也拒绝并返回 `E_FORBIDDEN`），不参与懒安装。原图自带"规划/在建"标注，改状态只需改 JSON。
- `anchorLocId`：本房间尚未安装该 `loc` 实体时，首次 `travel` 过去先经 Arbiter 懒安装（实体 + 双向 `located_in`）；锚点可以也是未安装的 canon 场景，递归处理，深度上限 8。初始 5 个 seed 场景不需要该字段。
- `category` 只用于前端筛选/图标/图例，不参与世界状态。
- `links[].kind`：`module`（可用的玩法模块 id）/ `npc`（固定 NPC）/ `dialogue`（本场景对话）/ `scene`（相邻场景，仅展示，移动仍走 `map.travel`）。
- 场景 `id` 必须是 `world_map.json` 的 seed 场景 id、已发布用户场景（`loc_user_*`），或带 `anchorLocId` 的 canon 新场景（初始未安装，首次 `travel` 懒安装）。
- `dialogues[].lines` 是**种子台词**，由导演 `npc.scene` 顺序输出；不允许写进 `narrative` 以外的状态。

### 2.2 `content/modules/map/data/npc-schedules.json`

```jsonc
{ "schemaVersion": 1,
  "schedules": { "npc_zhou": { "morning": "loc_teaching_1", "noon": "loc_canteen",
    "afternoon": "loc_teaching_1", "evening": "loc_playground", "night": "loc_dorm3" } } }
```

- 5 个 phase 与代码一致：`morning|noon|afternoon|evening|night`。缺 phase 或目标不合法时该 NPC 本 tick 不动。
- 目标不要求相邻：模块沿 `located_in` 通路 BFS 取最短路径，逐跳 `move.to`（Arbiter 逐条试算，同批多跳合法）。

## 3. 模块 `map`（`content/modules/map/module.ts`）

manifest：`id:"map"`、`priority:20`、`intents:["map.travel","map.look"]`、`tools:["map.travel","map.look"]`、`triggers:[5 phase]`、`views:["map"]`。**只读 `data/*.json`，不写文件，不调 LLM。**

### 3.1 `intent` / `tool`

输入格式（UI 与工具统一，`ModuleHost` 只认英文关键词）：

- `map.travel <locId>`：目标必须是 live `loc`。产出：沿当前通路 BFS 的逐跳 `move.to`（当前点直达则 1 条；不可达返回 `{ok:true, proposals:[]}` + facts）。末尾追加 `attr.set` 写玩家 `coord_x/coord_y`（目标场景坐标），以及**恢复镜头**的 `scene.set`：`locId=<目标>`、`presentIds=1(玩家)+目标场景当前 NPC`。
- `map.look`：不写状态，返回 `facts`：`【场景名】(x,y) 描述` + `在这里：NPC/玩家名` + `可做：<link.label>(<kind>)`。
- **路由让位（M5）**：输入含交易意图（买/卖/退/多少钱/价格/来一…/要一…）时 `intent` 主动弃权（`ok:false`），让 `ModuleHost` 继续问 `trade`——"去食堂买面包"是买东西不是走路，"看看面包多少钱"也不该被 `map.look` 截走。仅限 `intent` 路径；`tool("map.travel", …)` 显式调用不受影响。

`facts` 会进叙事（`Turn` 只取 proposals，facts 用于模块内提示；UI 自行读 `/map`）。不自动改 NPC 位置。

### 3.2 `tick(ctx, phase)`

1. 读 `npc-schedules.json` 取本 phase 目标；在 `ctx.state.entities` 找 `kind:"npc"` 且 live。
2. 当前地点 = `located_in` 边 `from=npcId` 的 `to`（缺失则跳过）。
3. BFS 通路（`located_in` 双向）得到逐跳路径 → 为每一跳产 `move.to{actorId:npcId, locId:hop}`，并产 `attr.set` 写该 NPC 的 `coord_x/coord_y`（每跳后按场景坐标更新，最终为终点坐标）。
4. **镜头保护**：`actor.moved` 投影会让 solo 房间镜头跟随任何 actor（含 NPC）。tick 末尾必须产 `scene.set{locId:<玩家当前位置>, presentIds:<玩家+最终在该场景的 NPC>}`（若已无变化可省）。
5. 无路径/无目标：跳过该 NPC，不产错误。

### 3.3 `init` / `context` / `view`

- `init`：校验数据文件可读（非法只 log，不 throw）。
- `view`：返回 `lists`：`map`（每个场景 `id/name/x/y/presentNpcIds`）与 `npc`（`id/name/locId`）。全量、纯读；前端真实数据以服务端 `/map` 为准。
- `context`：返回 `{focus:[locId], pins:[npc ids...]}` 可选，不强制。

## 4. 服务端 `apps/server/src/map.ts`（MapService）

统一错误对象 `{ ok:false, code: ErrorCode, message:string }`（复用闭集错误码）；HTTP 200 表示"游戏层拒绝"，500 只表示未预期异常。**房间入口先判存在性（issue #37）**：`:roomId` 不存在或是世界层房间 → HTTP 404 `E_ROOM_NOT_FOUND`，不落到 MapService、不产生任何日志（判定见 `apps/server/src/room-exists.ts`）。

| 方法 | HTTP | 入参 | 返回 |
|---|---|---|---|
| `getMap(roomId, actorId)` | `GET /api/v1/rooms/:roomId/map` | — | `{ok:true, map:MapView}` |
| `travel(roomId, actorId, locId)` | `POST /api/v1/rooms/:roomId/map/travel` | `{locId}` | `{ok:true, scene, events, map}` / `{ok:false,code,message}` |
| `tick(roomId, {advance?})` | `POST /api/v1/rooms/:roomId/map/tick` | `{advance?:boolean}` | `{ok:true, events, moved, map}` |
| `openDialogue(roomId, actorId, sceneId, dialogueId)` | `POST /api/v1/rooms/:roomId/map/dialogue` | `{sceneId,dialogueId}` | `{ok:true, npc, lines, sessionId}` |
| `createDraft(body)` | `POST /api/v1/map/drafts` | `{name,idea,anchorLocId,x?,y?}` | `{ok:true, draft}` |
| `getDraft(id)` | `GET /api/v1/map/drafts/:id` | — | `{ok:true, draft}` |
| `listDrafts(token)` | `GET /api/v1/map/drafts` | header `x-admin-token` | `{ok:true, drafts}` |
| `reviewDraft(id, token, body)` | `POST /api/v1/admin/map/drafts/:id/review` | `{action:"approve"|"reject",note?}` | `{ok:true, draft}` |
| `publishDraft(id, token, body)` | `POST /api/v1/admin/map/drafts/:id/publish` | `{action:"approve"|"reject",note?}` | `{ok:true, draft, scene?}` |
| `retryGenerate(id, token)` | `POST /api/v1/admin/map/drafts/:id/generate` | — | `{ok:true, draft}`（生成失败返回 §7 既有错误码，如 `E_LLM_TIMEOUT`/`E_LLM_FORMAT`，状态保持 `approved`） |

管理员鉴权：`x-admin-token` 必须等于 `GALGAME_ADMIN_TOKEN`（**没有默认口令**；未配置时服务端每次启动随机生成并只打印到控制台），不等 → `{ok:false,code:"E_FORBIDDEN"}`；比较使用常量时间等长哈希。**无用户账号系统**，玩家端只读自己 draft id。

### 4.1 `MapView`

```ts
interface MapView {
  worldId: string; width: number; height: number;
  image: string | null;             // 底图相对路径；null = 纯色底
  clock: { day: number; phase: Phase; tick: number };
  player: { actorId: string; locId: string };
  scenes: Array<{
    id: string; name: string; desc: string; tags: string[];
    x: number; y: number;
    status: "built" | "under_construction" | "planned";
    category: string;
    origin: "canon" | "user";
    installed: boolean;            // 本房间世界是否已有该 loc 实体
    presentNpcIds: string[];       // 实时（located_in）
    residentNpcIds: string[];      // 数据里 links kind=npc 的固定 NPC
    links: Array<{ kind: "module"|"npc"|"dialogue"|"scene"; id: string; label?: string; available: boolean }>;
  }>;
  npcs: Array<{ id: string; name: string; locId: string; x: number; y: number }>;
  published: string[];             // 已发布用户场景 id
}
```

坐标来源优先级：**场景模板坐标（世界地图数据）优先**，模板缺失时才退回实体 `attrs.coord_x/coord_y`，最后 `(0,0)`。这样旧存档里 1000×640 时代的旧坐标不会把点位甩到左上角；种子场景数据来自 `content/modules/map/data/world_map.json`，用户场景来自 `published.json`，同 id 以 canon 数据为准。NPC 点位在当前所在场景中心附近按 id 排序做确定性小偏移，避免同场景多个 NPC 完全重合（纯展示，不影响 `located_in`）。地图点位按 `world_map.json` 的 `status` 展示，已建成但本房间未安装的点位仍可 `travel`（触发懒安装）。

### 4.2 `travel` 语义

1. 解析目标场景（模板或 `published.json`）。不存在 → `E_SCENE_NOT_FOUND`。
2. `status !== "built"` → `E_FORBIDDEN`（规划/在建点只展示，不进入、不安装）。
3. 目标为已发布但本房间未安装，或 canon 新场景（带 `anchorLocId`）尚未安装 → 先 `Arbiter.apply` 懒安装：`entity.create{id,kind:"loc",name,attrs:{coord_x,coord_y},tags,origin:"ai"|"seed",canon:false}` + `link.create{located_in, from:anchor, to:id}` + 反向边（双向，保证 `buildView.exits` 两向都能看到）。用户场景 `origin:"ai"`，canon 新场景 `origin:"seed"`。**发布端点本身无 roomId，只写 `published.json`，不写任何房间世界状态。** 懒安装是幂等的：每次 `travel` 都检查实体与双向边，缺什么补什么（上次半途失败可自愈）；锚点未安装则递归先装，深度上限 8。初始 5 个 seed 场景（canon 建房时已写实体）不经过这一步。
4. `Turn.run`，输入固定 `map.travel <locId>`，`skipLLM:true`（省成本；叙事由前端用 `scene.desc` 展示），收集 SSE 事件到 `events`。返回前整包走 `maskTurnEvents`（snapshot → `unknownPlaceholders` → `maskNamesDeep`，见 `apps/server/src/view-names.ts`）：事件里 `turn.delta/facts/patch` 的未认识 NPC 真名换成占位名，场景台词同样脱敏，与 `/turns`、`/events`、`/state`、`/history` 同口径（issue #53）。**失败响应（`ok:false`）同样走这一层**：`message` 文本里的未认识 NPC 真名换成占位名，错误码与场景 id 不含人名不受影响，已知（`knows_name=true`）名字原样保留（issue #58）；早期失败拿不到快照时由 `maskTurnEvents` 回退到 `store.snapshot`。
5. 从 turn 结束后的新 state 组装 `map` 与 `scene`。**必须再校验玩家实际位置**（`state.room.scene.locId === locId` 或该 actor 的 `located_in` 指向目标）：地图模块对"同点/不可达"会返回 `ok:true + 空 proposals`，Arbiter 部分应用也返回 `ok:true`，所以只信 turn 事件会出现"假到达"；未到达 → `E_NOT_ADJACENT`。
6. 玩家位置以 `state.room.scene.locId` 为准；前端只在 `map.player.locId === 目标场景` 时展示到达叙事。

### 4.3 `tick` 语义

- `advance:true` 时把 `time.advance{phase:<下一 phase>}`（`proposal.by:"tick"`、cause `{type:"tick"}`）与 `ModuleHost.tick(ctx, phase)` 收集到的 proposals 合成**同一批**交给 `Arbiter.apply`（默认 atomic）：任一环节失败整批不落库，**时段不会单独提前**，重试也不会重复推进（issue #38）。旧实现先单独 apply `time.advance`，后阶段失败无法撤销。
- 提交前对模块 proposals 做 `Arbiter.dryRun` 预检；`time.advance` 不进 dryRun：3.2.1 起它按信封来源判定（不认 `proposal.by`），dryRun 的 `arbiter.dryRun` 来源不被信任，由带 `cause {type:"tick"}` 的 apply 一并裁决。
- 模块拿到的 `ctx.clock` 仍是推进前状态；目标 phase 以 `tick(ctx, phase)` 的显式参数为准。
- `advance:false` 只按当前 phase 重排 NPC。
- 本端点不调用 LLM、不发 `turn.*` 事件；无提交时 `events` 为空。
- 出站同样经 `maskTurnEvents`：`apply` 返回的 envelopes（payload 文本）与 `moved` 摘要里的未认识 NPC 真名一并换成占位名，已知（`knows_name=true`）名字原样保留（issue #53）。**失败响应（`ok:false`）同口径**：`dryRun`/`apply` 被拒或抛错时返回的 `message`/`detail` 也过同一层掩码，错误码不受影响（issue #58）。

## 5. 场景草案状态机（`data/map/drafts.json`）

```
pending_review --管理员 review approve--> approved
pending_review --管理员 review reject---> rejected
approved --自动触发/重试 AI 生成--------> generating --成功--> generated_pending_review
generating --失败--> approved（记录 error，可重试）
generated_pending_review --管理员 publish approve--> published（安装进 published.json）
generated_pending_review --管理员 publish reject---> rejected
approved --管理员 publish reject---> rejected
```

- 非法迁移 → `{ok:false,code:"E_ILLEGAL_OP"}`。
- 草案：`{id:"draft_<8hex>", status, name, idea, anchorLocId, coords:{x,y}, generated?, error?, history:[{at,action,actor:"player"|"admin"|"ai",note?}], createdAt, updatedAt}`。
- 新建时 `anchorLocId` 必须是模板场景或已发布场景；`name` 2–24 字，`idea` 10–300 字；坐标缺省 = 锚点 + 随机半径 40–90，clamp 到地图内。
- AI 生成：读 `content/prompts/map.scene.md`（`PROMPT_VERSION: map-scene-1`），要求模型返回严格 JSON：
  `{ "name": string, "desc": string(40–160), "tags": string[](≤4), "links": [...], "dialogues": [{ "title", "npcId"(必须是已有 npc), "lines": string[](1–5) }] }`。
  zod 校验；失败重试 1 次；再失败保持 `approved` 并记录 `error`。生成结果**只存草案**，不落世界。`dialogues[].npcId` 与 `links` 中 `kind=npc/scene` 的 `id` 必须存在于 canon / 场景表，否则按 `E_LLM_FORMAT` 让模型重试。
- 发布：只把场景模板写入 `data/map/published.json` 并置 `published`；`entity.create` + 双向 `located_in`（新场景 ↔ `anchorLocId`）在每个房间首次 `travel` 过去时懒安装（见 §4.2）。删除/下架不做（不在本次范围）。
- 发布场景 id：`loc_user_<8hex>`（必须 `loc_` 前缀，满足 `entity.create` 校验）。tags ≤ 16、links ≤ 12、dialogues ≤ 8。

## 6. 场景对话（导演 `npc.scene`）

- 文件：`content/directors/npc.scene.ts`，实现 `DialogueDirector`，`directorId:"npc.scene"`。
- 输入 `spec.seed = { sceneId, dialogueId, npcId, npcName, lines:string[] }`，`maxTurns = min(8, lines.length)`；每 turn 输出当前行作为该 NPC 的 `utterance`，最后一行后 `done:true`；**不产 Proposal、不调 LLM、不写记忆**。
- `bootstrap.ts` 已扫描 `content/directors/*.ts` 并注册所有导演（`npc.scene` 不需要单独登记）。
- `MapService.openDialogue` 校验 scene/dialogue 存在、**玩家当前就在该场景且 `presentIds` 含玩家**、NPC 存在且在本房间实体表（live），构造 spec，跑完 session 后关闭，返回台词数组；玩家不在场景 → `E_NOT_ADJACENT`，不在场 → `E_NOT_IN_ROOM`，NPC 不存在 → `E_ENTITY_MISSING`。不强制 NPC 与玩家同场景：AI 生成的场景对话可能是"门后的声音/电话"，强校验会让生成内容几乎不可用。

## 7. 前端（`apps/web`）

- 入口：标题页（`TitleScreen.tsx`）→「进入游戏」展开三种身份，点身份卡才建房；身份/开局文案来自内容数据 `content/scenarios/openings.json`，经 `GET /api/v1/scenarios` 下发（`docs/03` §5.2.6），前端不硬编码文案；端点不可用时显示「无预设开局」并允许「直接开始」（开场只有一行提示，不编造内容）。「继续上次」读 `localStorage` 的 `lastRoomId` 后 `GET /state` 续局，房间已失效则清记录并提示新建；契约版本取自 `GET /api/v1/health`（不写死）。标题页任一入口都是"独占步骤"：主菜单整体收起，只留该步骤内容与「← 返回」。标题页「接入真实模型」面板调 `GET/POST/DELETE /api/v1/settings/llm`（`docs/03` §5.2.2），Key 不进 localStorage、不回显。
- 顶部 tab：`对话 / 地图 / 图鉴 / 审核`（不改路由库；进入游戏默认落在「对话」）。
- 对话：进入房间时先把开场剧情铺进对话流（身份行 + 开局的若干段正文 + 第一条建议；段数由 `openings.json` 决定），之后 `POST /turns` 的 SSE 把「玩家输入 → `turn.delta` 叙事 → `turn.facts` 事实」依次追加；`turn.patch` 覆盖 state，`turn.ui` 供面板。中文输入能否路由到模块由 manifest 的 `capabilities.keywords` 决定（`docs/01` 已规定）。叙事原文不入事件库，所以「继续上次」只恢复世界状态、不回放旧对话。
- 点 NPC / 场景隔离（issue #21-1）：2D 地图上会画出所有 NPC（`MapView.npcs[].locId`），但**只有当前场景里的人才打开对话**（`planNpcTalk`，`apps/web/src/npc-presence.ts`；当前场景取 `view.position.locId`，刚进房间尚未有 View 时以 `MapView.player.locId` 兜底）。点不在场的人**不建立对话对象**，对话区提示「TA 不在这里（现在在「场景名」）」并给「前往 TA 所在地」——复用 `POST /map/travel`，成功后等 `view.position.locId` 切到目标场景再自动选中该 NPC；`travel` 失败（未建成/不可达）在提示条里显示可读错误，不静默。`locId` 缺失、或场景表里查不到该点（数据缺失）时不提供前往按钮，只说明原因。自测：`apps/web/src/npc-presence.test.ts`。
- 回合失败重试（issue #21-3）：`turn.error` / `turn.rejected` 事件带 `retryable`（`docs/03` §2.3）；为 `true` 时对话区错误条显示「重试」，点击用**新的 `clientTurnId`** 重发上一次玩家输入（不重复打印玩家行、不清空正在编辑的输入），成功即清错误、失败保留可再试。前端**不自动重试**（避免重复扣费/重复回合），传输层/HTTP 错误不显示重试按钮。可重试文案与判定抽在 `apps/web/src/turn-error.ts`（`turn-error.test.ts`）。**换场景后旧重试失效**（评审 P2）：`view.position.locId` 变化时清掉待重试的上一回合（`shouldDropRetryOnMove`），如当时重试按钮正显示则收掉并提示「已离开原来的场景，上次失败的重试已失效」；点重试前还会用当前 WorldState 复核目标仍在当前场景（`targetStillInScene`：`scene.presentIds` 命中或 `located_in` 指向脚下），不在则禁用并提示，**不会**用旧目标构造「对 X 说：…」绕过场景隔离（`npc-presence.test.ts`）。
- 图鉴：**只渲染服务端 `GET /api/v1/rooms/:roomId/gallery` 返回的 `GalleryView`**（`docs/03` §5.2.5），前端不读 `state.entities[].attrs`、不碰属性键与分档阈值——服务端按 `content/registry/attrs.json` 的 `label/unit/min/max/visibility/display.hidden` 生成读数：`public` 给精确值 + 进度条；`secret` 只给「低/中/高」分档（响应不含精确数值）；`self` 对他人只给分档（文本降级为「—」）；`hidden` 属性不出现；未设置值的读数显示「—」。**`met = 知道名字（`knows_name` 为 true）`**——一级认识口径：同处一地、被看见都不算认识；未认识时地图标记 / 对话栏 / 图鉴一律用占位名（**优先用 `content/scenarios/npcs.json` 的 `appearance` 外貌描述**，如「穿白衬衫、袖口别着校徽的男生」；缺描述时退回按实体 id 排序的「一位 / 另一位 / 第三位…陌生的同学」），服务端不下发真名、不返回档案/位置/读数。档案 role/traits/line 来自 `content/scenarios/npcs.json`。头顶气泡的 `mutter` 同口径——只由房间图鉴在 `met=true` 时下发，`CampusMap` 从当前房间的 `/gallery` 取（拉不到图鉴就不出气泡）；`/api/v1/scenarios` 的 `npcs[]` 只有 `id`/`appearance` 两个公开字段，标题页/开局页读不到任何档案（issue #54）。改名/删除注册表属性只会让该读数消失或按新声明出现，不会静默崩。
- 陌生人开场（`knows_name=false`）：`/map/dialogue` 在剧本台词前补一句「（他看了你一眼，显然不认识你）「同学，你是？怎么称呼？」」。`content/modules/introduce` 只写私忆：**自述姓名**（「我叫X/叫我X」）→ 在场 NPC 各记一条"这位同学自我介绍叫X"；**问名字** → 各记一条"这位同学问了我的名字"。它**不置位** `knows_name`——解锁由服务端在 `turn.commit` 之后做：有 `targetNpcId` 且玩家问名字时只解锁该目标（要求目标在场），无目标时按台词里是否真的出现姓名判定（`apps/server/src/name-unlock.ts`）。图鉴随 `knows_name` 即时解锁（服务端派生视图）；前端在状态刷新时（`stateRev`）重拉 `/gallery`，不需要手动切 tab。
- 文本逐字打出：`apps/web/src/typewriter.ts` 统一驱动开场剧情、流式叙事与 facts——标点分小停顿（160ms）/大停顿（320ms），流式缓冲积压超过 140/320 字时步幅加快；点击对话区或再次输入可立即跳过。`apps/web/src/sfx.ts` 用 Web Audio 合成按键音（零依赖、可静音）；页面进入 / 切 tab / 新对话行均有 CSS 过渡，`prefers-reduced-motion` 时关闭。
- 地图：`map.width×map.height` 画布（当前 6000×4500，底图 `map.image` 铺满）；视口支持滚轮/按钮缩放（fit–4x）、拖拽平移、重置；场景按像素坐标绝对定位，标记反向缩放保持可读。
- 点位状态：`built` 可点击前往（`POST /map/travel`），成功后把 `【场景名】描述` push 进 story log 并刷新 state/map；`under_construction` / `planned` 点击只选中并在详情显示「在建，暂不可进入」/「规划中，尚未建成」，不发 travel。图例固定显示三态；当前所在点与选中点单独描边。
- 场景详情：名称、状态徽章、类别、描述、坐标、tag、links（module=灰底 chip；npc=在场/常驻标签；dialogue=按钮，点开拉台词并按 `npc.name` push 对话行）；「推进时段」按钮调 `/map/tick {advance:true}`，把 `moved` 摘要 push 进日志。
- 审核：管理员 token 输入（存 `localStorage`）；列表显示 status；`pending_review` 显示「通过/拒绝」，`generated_pending_review` 显示生成预览 +「发布/拒绝」；操作后刷新。玩家创建表单：名称 + 想法 + 锚点场景选择。
- 只渲染服务端数据，不缓存权威状态；不新增依赖。
