# v2 群聊对话：前端影响清单

> 本分支只改引擎与数据，**不改 `apps/web`**。以下记录前端后续必须做的事，避免遗漏。
> 后端会新增一组 `ConversationEvent`，走现有 SSE 通道（事件名 = `type`），不复用 v1 的 `turn.*` 事件。

## 必须新增的交互

1. **@ 在场 NPC**：从 `scene.presentIds` 渲染可选参与者列表；支持"全体"和"多选（≥2）"。@多人会唤醒场景 agent。
2. **说话模式切换**：`broadcast`/`addressed`/`whisper`/`signal` 四种，文案直接用 `utterance-modes.json` 的 `label`（数据驱动，前端不要写死中文名）。
3. **动作输入**：`whisper`/`signal` 模式必须填 `action`（引擎会校验），`coverAction` 可选（缺省由词表生成）。
4. **插话按钮**：点击后发 phase 切换请求；此时 NPC 只听不说，等玩家发言完自动恢复。按钮要显示"等待你说话"状态；后端已实现 `listenTimeoutMs` 自动恢复（默认 30s，配置在 conversation-policy.json），前端应同步倒计时并在收到 `conversation.phase speaking` 时清除等待态。
5. **自主续聊**：玩家不说话时 NPC 也会继续发言；前端要能持续渲染 `conversation.utterance`，而不是等玩家回合结束才刷新。

## 渲染规则（关键：不同人看到不同内容）

- `conversation.utterance.payload = { to, channels, content?, action?, notice? }`。
- **前端只渲染自己 actorId 收到的那条 payload**，不得拿说话者的原文兜底渲染给其他人。
- 四种模式的玩家视角：
  - `broadcast`：内容 + 动作
  - `addressed`：内容 + 动作 + 「对 X 说」标记
  - `whisper`（玩家非目标）：**只有神色动作**，没有内容、没有"有人在悄悄话"的提示
  - `signal`（玩家非目标）：**只有低信息动作**（如"目光扫过桌面"），看不出含义
- `conversation.mental` **禁止渲染给玩家**（只进调试面板/审计日志）。
- `conversation.scene` 用独立样式（场景描述），开场广播与唤醒总结区分显示。
- `conversation.phase` 改变插话按钮状态。

## 兼容与降级

- v1 的 `turn.*` 事件继续存在（v1 入口未改）；前端可以两套并存，按房间/会话类型切换。
- 旧 UI 不认识 `conversation.*` 时应忽略，不能因为未知事件报错。
- 事件里的 `audience` 字段仍由服务端在投递前过滤；前端**不要**自己拿全量日志再过滤（会泄露悄悄话内容）。
