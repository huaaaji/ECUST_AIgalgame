## 1. 逐项证据与建议

### 1.1 完全兼容的部分

- **契约**：`packages/shared/src/contract/v2.ts` 只是新增类型，`packages/shared/src/index.ts` 加了一行 re-export；`scripts/check-contract.ts` 8/8 通过，`CONTRACT_VERSION` 仍是 3.3.0。
- **Arbiter / Store / Memory / Transport**：v2 的每一次写入仍是 `Proposal[] → arbiter.apply(atomic) → store.append → memory.ingest(ev)`（`packages/engine/src/v2/conversation.ts:324-337`），没有直接写文件/状态；`scene.changed` 仍以 `scene.presentIds` 为唯一在场真源。
- **审核**：`v2/audit.ts` 复用 `AuditGate.punish`（`packages/engine/src/audit.gate.ts:78`），警告/扣分/删档线仍由 `content/registry/policy.json` 决定。
- **trade**：`content/modules/trade/module.ts` 只产出 `attr.delta` + `entity.create` + `link.create`，不碰对话通道；v2 不加载模块，互不干扰。

### 1.2 需要适配

1. **LLM 调用预算（llm + audit）**：v2 每轮对**每个在场 NPC**各调一次模型，再对每个 speak/think 的字段审一次；`content/v2/conversation-policy.json` 目前只有 `npcHardCap`/`maxTurns`，没有 `maxLlmCallsPerTurn`。建议在策略里加调用上限与并发上限，由 `ConversationHostV2` 统一计数；否则 5 个 NPC 的房间一次发言可能产生 10+ 次调用。
2. **私忆六道闸门**：`packages/engine/src/memory.gate.ts` 的 G1–G6 只在 v1 `turn.ts` 路径调用；v2 `memoryProposals()` 直接产 `memory.write`，Arbiter 只做形状校验。建议 v2 在生成 Proposal 前调用 `applyMemoryGates`（至少 G1 在场 / G4 重要度 / G6 配额），避免每个 NPC 每轮都能无限写秘密记忆。
3. **地图换地点唤醒**：`v2/scene.ts` 的 `shouldWake` 已支持 `locationChanged`，但 `v2/conversation.ts:192` 固定传 `false`。建议在 `move.to` 成功后由 `ConversationHostV2` 记一次地点变化，下一轮触发场景总结。

### 1.3 语义冲突（需产品决策，不是 bug）

- **`core.say` vs v2 发言**：`content/modules/core/module.ts:49` 的 `say()` 只返回 facts「你说：…」，v2 会话也产 `conversation.utterance`。如果未来把 v2 接入同一条 HTTP 入口，玩家一句话会既有模块叙事又有会话发言。建议：启用 v2 时禁用 `core.say` 意图，或让 v2 入口绕过 ModuleHost。
- **v1 导演 vs v2 NPC agent**：`content/directors/npc.plot.ts` / `npc.smalltalk.ts` / `npc.scene.ts` 实现的是 `DialogueDirector`（按轮 step），v2 是 `NpcAgent.decide`（按消息一次性决策）。两者可共存但不可混用同一个 session；迁移策略建议：新场景用 v2，旧地图对话（`MapService` 的 `dialogue` 端点）继续用 v1，避免一次性重写。

### 1.4 未接线（最大缺口）

- `apps/server/src/bootstrap.ts` 仍只装配 v1 `DialogueHost`（:172），没有 `new ConversationHostV2(...)`。
- `apps/server/src/routes.ts` 没有 `/api/v1/conversations/*` 端点；`apps/web/src/api.ts:181` 的 `dispatch()` 只处理 9 种 `TurnEvent`。
- 因此**当前 v2 只能在测试/引擎层使用，浏览器还玩不到**。这部分已列在 `docs/v2/前端影响清单.md`，本分支按用户要求不碰前端。

## 2. 结论

引擎内部的适配度好：三个不变量（I1/I2/I3）未被破坏，12 op 未动，老模块不需要改代码就能继续跑。

真正的缺口都在**边界**：服务端未装配、前端未接线、以及三个需要补的策略闸门（LLM 预算、私忆六闸门、换地点唤醒）。建议在把 v2 暴露给玩家之前，先补这三项；`core.say` 与 v1 导演的取舍需要产品决策。
