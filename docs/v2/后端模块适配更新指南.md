# 后端模块适配更新指南（CONTRACT 3.6.0，v2 已合入 main）

> 读者：`content/modules/**` 的模块作者、服务端集成者、内容/数据维护者。
> 范围：`dev/v2` 合入 `main`（merge commit `02a3318`）带来的契约面变化。原则不变：**Module 算数、Director 说话、Engine 记账**；模块只产 `Proposal`，不直接写库。

## 1. 契约变化总览

| 项 | 变化 | 影响 |
|---|---|---|
| `CONTRACT_VERSION` | 3.5.0 → **3.6.0**（minor） | 只增不改；v1 的 12 个 op 语义不变 |
| op 原语 | 12 → **13**：新增 `msg.send` | 新玩法可用；旧模块不受影响（但 manifest 要升版，见 §2） |
| `API_VERSION` | 2 → **3** | `manifest.json` 的 `apiVersion` **必须写 3**（zod `z.literal(3)`，写 2 会被拒绝加载） |
| `ErrorCode` | 新增 `E_DIALOGUE_NOT_FOUND` / `E_MODULE_FAULT` / `E_AUDIT_UNAVAILABLE` 等（共 39 个） | 模块/服务端按 `{ ok:false, code }` 处理 |
| 事件 | `msg.sent` 已登记进 `content/registry/events.json` | 想消费就声明 trigger |
| `Envelope` | 复用既有 `audience?: ActorId[]` | `msg.sent` 带 `audience:[from,to]`，传输层据此过滤 |
| `SCHEMA_VERSION` | 仍 2 | 存档结构不变 |

## 2. 模块必做：manifest 升到 `apiVersion: 3`

`content/modules/*/manifest.json` 四条（study/trade/map/...）已升 3。**自己维护的模块**若仍是 2，引擎会拒绝加载（fail-closed）。改完跑：

```bash
npm run check:contract   # manifest apiVersion 与 API_VERSION 一致
npm test -- <你的模块>
```

## 3. 新原语 `msg.send`（第 13 个 op）

```ts
{
  op: "msg.send",
  args: {
    from: ActorId, to: ActorId,
    kind: "gossip" | "reply" | "player" | "system",
    content: string,          // 1..400 字
    rootId?: Id,              // 八卦根消息
    replyTo?: Id,             // 回复的消息
    hop?: number,             // 0..12
    confidence?: number,      // 0..1
    visibility?: "private",   // 目前只有 private
  },
  reason: string,
  by: string,
}
```

引擎校验（不通过 → `E_PRECONDITION`，整批 atomic 回滚）：

- `trustedOrigin`: 只有 `engine` / `tick` / `dialogue` / `plot` / `gossip` 能发 `msg.send`；**普通玩法模块不能直接发私信**（避免绕过审核与预算）。
- `from !== to`、双方实体存在且未 tombstone、`kind` 枚举内、`content` 1~400。
- `rootId`/`replyTo` 必须是 Id；`hop` 0~12 整数；`confidence` 0~1。
- **`rootId` 存在 ⇒ `hop >= 1` 且 `confidence <= 0.95`**（转发必须逐跳衰减；回复用 hop 0/confidence 1，但回复不写 rootId 的派生路径——以 `arbiter.ops.ts` 实现为准）。
- `forbidReveal` 命中直接拒。
- 事件 id = `msg_${roomId}_${cause.id}_${seq}`，事件类型 `msg.sent`，`audience:[from,to]`。

**用法边界**：`msg.send` 只解决「私信记录 + 可见性」；叙事仍走 v1 `dialogue.*` / v2 会话。模块想「让 NPC 传话」→ 产 `msg.send` 提案即可（但要能过 trustedOrigin；普通模块应改为通过对话/导演链路）。

## 4. 记忆写入的新语义

- `memory.write` 仍只走 Arbiter；新增 `visibility: "private" | "secret" | "public"` 的既有语义（v2 起 gossip 私忆为 `private`，`signal` 为 `secret`）。
- gossip 写私忆时会带 `sourceRefs` 与 `tags:["八卦", rootId]`，并经 `MemoryGate` 的 `trustedChannel: "gossip"` 通道（`packages/engine/src/memory.gate.ts:174`）；**模块自己写记忆不要伪造 `sourceRefs`**，否则会被当作可信来源放行。
- 记忆可见性由引擎按 mode/数据决定，模块不要自己决定谁能看。

## 5. 数据与配置

| 文件 | 变化 |
|---|---|
| `content/v2/utterance-modes.json` | 4 个说话模式（broadcast/addressed/whisper/signal）+ `dm`（微信私信，`targetPresence:"any"`） |
| `content/v2/conversation-policy.json` | 新增 `autonomy{minReplyIntervalMs,maxMessagesPerNpcPerHour,maxNpcCallsPerTick,maxTurnsPerTick,idleTimeoutMs,playerPresentGraceMs}`、`llm{temperature,maxTokens}`、`messages{...}` 文案 |
| `content/v2/gossip-policy.json` | 微信/八卦策略：`minReplyIntervalMs`/`maxMessagesPerNpcPerHour`/`maxNpcCallsPerTick`/`maxHops`/`confidenceDecay`/`messages` |
| `content/registry/events.json` | 新增 `msg.sent` |

加载器都是 **fail-closed**（坏数据抛错，不静默降级）；服务端还有 `GALGAME_GOSSIP_SCAN_MS`（默认 30000ms）控制八卦波次扫描。

## 6. 服务端集成现状（合入后）

已接线：`/messages` 三端点、SSE、`/events` 的 `audience` 过滤、gossip 定时波次、`TalkBudget`、审核。
**未接线**：`ConversationHostV2` 尚无 HTTP/SSE 入口（群聊仍走 v1 `/turns`）；多房间会话恢复、`npc.spoke` 事件（v2 不产）也仍缺。
