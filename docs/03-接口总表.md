## 0. 命名总则

### 0.1 六条规则

| # | 规则 | 反例 |
|---|---|---|
| R1 | **点分命名空间**：`<ns>.<verb>`，全小写，单词用 `_` 连接 | `buyItem` / `Trade.buy` |
| R2 | **名词用单数**，不用复数 | `items.list` ✗ → `item.list` ✓ |
| R3 | **动词用祈使式**，不加时态 | `bought` ✗ → `buy` ✓ |
| R4 | **模块内接口必须带模块 id 前缀**：`<moduleId>.<verb>` | 模块 `trade` 的工具只能叫 `trade.*` |
| R5 | **保留命名空间禁止被模块占用**（见 §0.2） | 模块不能叫 `mod` / `npc`；唯一例外是引擎自带的基础动作模块 `content/modules/core` |
| R6 | 名字一旦随版本发布，**只增不改不删**；废弃用 `deprecated` 标记并保留 ≥2 个版本 | 直接把 `trade.buy` 改名 |

### 0.2 保留命名空间

| 命名空间 | 归属 | 用途 |
|---|---|---|
| `core` | 引擎 | 移动/观察/等待/说话等基础动作（实现放在 `content/modules/core`，属于引擎自带模块，其他模块不得占用该前缀） |
| `world` | 引擎 | 时钟、地点、天气、事件 |
| `actor` | 引擎 | 玩家/NPC 通用能力（任何 actor 都能做） |
| `npc` | 引擎 | 自主行为、对话调度 |
| `mem` | 引擎 | 记忆读写 |
| `plot` | 引擎 | 剧情线/密谋 |
| `mod` | 引擎 | 模块元操作（`mod.load`、`mod.reload`） |
| `net` | 引擎 | 房间、成员、同步 |
| `view` | 引擎 | 视图数据下发 |
| `admin` | 引擎 | 仅本机/内网 |
| `x` | **AI 自由区**（见 §0.5） | AI 推演时临时产生的属性/标记 |

> 模块 id 不得与上表重名（启动时校验，冲突即拒绝启动）。

### 0.3 实体 ID 规范

```
<kind>_<slug>              例：npc_zhangsan, loc_classroom_2_3, item_bread
<kind>_<slug>_<n>          需要区分实例时：mem_1a2b3c, plot_0007
```

| kind | 含义 | 谁创建 |
|---|---|---|
| `plr` | 玩家 | 引擎 |
| `npc` | 非玩家角色 | 内容种子 / AI 推演 |
| `loc` | 地点 | 内容种子 / AI 推演 |
| `item` | 物品 | 内容种子 / AI 推演 |
| `fact` | 客观事实（canon） | 仅人工 |
| `lore` | 软设定（AI 可增删） | 内容种子 / AI 推演 |
| `plot` | 剧情线/事件 | AI |
| `mem` | 记忆条目 | 引擎 |
| `evt` | 事件（日志） | 引擎 |
| `room` | 房间（单人/联机） | 引擎 |
| `mod` | 模块实例 | 引擎 |

- `slug` 只允许 `[a-z0-9_]`，长度 2~32；中文名只存在 `name` 字段里，**不进 id**。
- ID 全局唯一，**永不复用**（删除 = `tombstone`，见 `02-数据格式.md` §6）。

**记忆的保留 ID（3.1.0 起）**：

| 名字 | 类型 | 说明 |
|---|---|---|
| `mem_world` | ownerId | 世界层永久记忆的固定 owner。**它不是实体**，`memory.write` 对它跳过实体存在性校验 |
| `room_world_<worldId>` | roomId | 每个世界一个保留房间，只存 `tier=permanent`，无成员、不可进入 |
| `mem_<contentHash 前 12 位>` | 记忆 id | 有 `contentHash` 时用它（永久层幂等键） |
| `mem_<roomId>_<turnSeq>_<seqInTurn>` | 记忆 id | 无哈希时用它；`turnSeq` = 回合信封 seq（时钟不推进也不同），`seqInTurn` = 本次 apply 内该条提案的序号（同回合同 owner 同 tags 也不撞） |

### 0.4 版本号

| 东西 | 字段 | 语义 |
|---|---|---|
| 接口契约（本文） | `CONTRACT_VERSION` | 语义化版本；破坏性变更 → major |
| 模块 | `manifest.apiVersion` | 整数，引擎只认 `1`（v1）、`2`（v2 群聊）、`3`（dev/v2 微信，见下） |
| 数据格式 | `schemaVersion` | 每个 schema 文件内 `$id` 尾段 |
| 事件 | `v` | 事件 payload 形状版本，默认 `1` |

> `apiVersion` 变更策略：**只有当 §3 的 op 原语集合变化时才 bump**。新增模块/工具/属性/事件类型**永不** bump（这就是"只加变量不改引擎"的机制保证）。
> dev/v2 新增第 13 个 op `msg.send`，因此 `API_VERSION 2 → 3`；老模块代码无需改，只需把 manifest 的 `apiVersion` 改成 3（语义未变）。

### 0.5 `x.` 自由区（AI 推演专用）

AI 在推演中产生的**临时属性/标记**一律放进 `x.` 前缀：

```json
{ "op": "attr.set", "args": { "entityId": "npc_zhangsan", "key": "x.mood_hint", "value": "躲闪" } }
```

- 引擎对 `x.*` **不做类型校验**，按 `number | string | boolean` 原样存。
- `x.*` 只能在**本房间内**可见，不进 canon、不进全局检索、**不得被叙事层当作硬事实引用**。
- 每回合 `x.*` 写入上限 8 条；单实体上限 32 个 key（超出按 LRU 淘汰）。
- 想让某个 `x.*` 转正 → 人工在 `content/registry/attrs.json` 声明正式 key，然后 `attr.set` 迁移。

> 这条是"AI 可以自由增减，但引擎不被污染"的关键闸门。

### 0.6 变更影响矩阵

| 你改了 | 必须做什么 |
|---|---|
| 新增模块 | 加一个目录 + `manifest.json`（启动自动扫描 `content/modules/*/manifest.json`，**无需登记**）。**不动引擎** |
| 新增属性 | `content/registry/attrs.json` 加一条 + UI 字段映射（可选）。**不动引擎** |
| 新增 LLM 工具 | manifest `tools` 加名 + 实现 handler。**不动引擎** |
| 新增事件类型 | `content/registry/events.json` 加一条。**不动引擎** |
| 新增 op 原语 | 本文 §3 + 引擎 `Arbiter` + bump `apiVersion`（dev/v2 已 2→3）。**动引擎（尽量避免）** |
| 改 op 语义 | bump `CONTRACT_VERSION` major + 全体模块回归 |
| op 只**新增可选**参数、旧参数旧行为不变 | bump **minor**（例：3.0.0 → 3.1.0 的 `memory.write` 新字段）；旧提案仍合法，不需要改模块 |
| 新增拒绝路径（旧提案可能开始被拒） | minor 但在 §10 变更表写明"新增拒绝"；若会让**已发布内容**失效则按 major |

> 判定顺序：先问"旧提案还能不能原样提交并得到原结果"。能 → minor；不能 → major。
> 3.1.0 属于 minor：`memory.write` 旧 6 字段语义不变，新字段只在显式传入时触发新路径；但新增了两条拒绝路径（世界层 `E_MEMORY_WORLD_MISMATCH`、旧 `visibility:"scene"` 归一为 public），所以 §10.10 不能用"全是只增"来概括。

## 1. 分层与名字归属

```
Client ──HTTP/SSE──> Transport ──Envelope──> Router
                                                │
                                             Turn.run
                                                │
                    ┌───────────────────────────┼───────────────────────┐
                 Modules                      Dialogue                 Memory
              (modules/*)                 (directors/*)            (engine)
                    └──────────────► Arbiter.apply ◄─────────────────┘
                                          │
                                     EventLog / Snapshot
```

- **只有 `Arbiter.apply` 能写世界状态**。模块、导演、记忆、UI 全部产出 `Proposal[]`。
- **只有 `Transport` 接触网络**。引擎不知道 HTTP/WS/SSE 的存在，只知道 `Envelope`。

## 2. 内部接口（TypeScript）

> 路径：`packages/shared/src/contract/`。这些类型是**冻结契约**，实现可换，签名不可随意改。

### 2.1 基础类型

```ts
/** 统一信封：所有跨子系统消息都用它 */
interface Envelope<T = unknown> {
  v: 1;                      // payload 版本
  id: string;                // 消息 id（evt_xxx）
  roomId: string;
  seq: number;               // 房间内单调递增，用于去重与断线续传
  ts: number;                // 服务器时间戳 ms
  actorId: string;           // 发起者：plr_* / npc_* / sys
  type: string;              // 见 §5
  payload: T;
  causedBy?: string;         // 触发它的上一条消息 id
}

/** 世界状态 = 实体集合 + 房间元信息 */
interface WorldState {
  schemaVersion: number;
  room: RoomState;
  entities: Record<string, Entity>;   // id -> 实体
  links: Link[];                      // 关系/持有/在场等边
  clock: GameClock;
}

interface Entity {
  id: string;
  kind: EntityKind;                   // plr|npc|loc|item|fact|lore|plot
  name: string;
  attrs: Record<string, AttrValue>;   // 键必须在 registry 或 x. 区
  tags: string[];
  origin: "seed" | "ai" | "system";   // 谁创造的
  canon: boolean;                     // 是否锁定
  status: "active" | "dormant" | "tombstoned";
  createdAt: number;                  // 游戏内回合序号
  updatedAt: number;
}

type AttrValue = number | string | boolean;
```

### 2.3 裁决器 `Arbiter` —— 唯一写入口

```ts
interface Arbiter {
  /**
   * 校验 + 应用 + 落日志。默认 **atomic：要么全成功，要么全回滚**（02 §4）。
   * 同一房间的 apply 在实现里串行排队，并发提交不会交错读同一份快照。
   */
  apply(roomId: string, ops: Proposal[], cause: Envelope, opts?: ApplyOptions): Promise<ApplyResult>;
  /** 只校验不落库、不消耗回合预算（干跑，给 UI 预览与测试用） */
  dryRun(roomId: string, ops: Proposal[]): Promise<ValidationResult>;
}

interface ApplyOptions {
  mode?: "atomic" | "partial";  // 默认 atomic；partial 是显式选择（坏条目丢弃、余下照做）
  expectedSeq?: number;         // 乐观并发：与当前 seq 不符 → 整批拒绝 E_SEQ_GAP
}

// 附：整回合预算（引擎内部，不跨包；Turn 创建并跨多次 apply 复用）
// `xWritesPerTurn` / `maxDeltaPerTurn` 是**整回合**限额，不是单次 apply 的限额：
// 同回合把提案拆成多次 apply 也绕不过。不传 turnBudget 时按 cause.causedBy（回退 cause.id）
// 自动归集，与 3.1.0 行为完全一致；传了则显式共享，并登记到回合键（同回合内未传预算的
// 入口，如审核处置 audit.punish，也继续用同一份计数）。
interface TurnBudget {
  delta: Map<string, number>;   // `entityId|key` → 本回合累计变化量
  xWrites: number;              // 本回合 x. 区已写条数
  memSeq: number;               // 本回合已写记忆条数（memory id 序号）
}
type ArbiterApplyOptions = ApplyOptions & { turnBudget?: TurnBudget };
// x 区预算口径（#41）：xWrites 只累计 attr.delta / attr.set 且属性键以 "x." 开头的提案；
// memory.write（含工作记忆与 tombstone）不计入 x 区预算，由 §8 的 G6 记忆配额单独约束。
// 因此双 NPC 的种子/工作记忆/tombstone 再多，也不会挤爆每回合 8 条 x 区额度。

interface Proposal {
  op: string;                       // §3 的 13 个原语之一（dev/v2 含 msg.send）
  args: Record<string, unknown>;    // 每个原语的参数见 §3
  reason?: string;                  // ≤60 字，写进日志便于排查
  by?: string;                      // 产生者：mod.trade / npc.director / engine.turn
}

interface ApplyResult {
  ok: boolean;                      // "这批到底提交了没有"：atomic 下有拒绝即 false；partial 下只要提交了就 true
  mode: ApplyMode;                  // 实际采用的语义，写进日志便于回放与审计
  seq: number;                      // 落库后的最新 seq
  applied: Proposal[];
  rejected: { proposal: Proposal; code: ErrorCode; detail: string }[];  // 必须能被调用方追溯到来源
  events: Envelope[];               // 本次产生的领域事件（atomic 失败时为空）
}

type ApplyMode = "atomic" | "partial";
```

**提交语义（v2.3.0 起明确）**

| 模式 | 谁来用 | 语义 |
|---|---|---|
| `atomic`（默认） | 玩家回合、交易、密谋落账 | 任何一条被拒 → 整批不落库；`ok=false`，`events=[]`，状态与 seq 不变 |
| `partial` | 显式需要的批处理（如一次写入多条非关键 x. 数据） | 坏条目进 `rejected[]`，余下照做；提交成功则 `ok=true` |

> **拒绝必须被编排层消费**：`Turn` 不允许"有 rejected 还 commit"。模型提案被拒 → 带原因修复最多一次；LLM 输出不是合法 JSON → 带解析错误重问一次（见 §2.4「两条路」）；模块提案被拒 → `E_MODULE_FAULT`；修不好 → `turn.error`，且不产生 `turn.delta`（叙事只能在裁决之后发）。

```ts
// 附：整批失败的形状 —— 没有"哪条 proposal 被拒"可说时用 error，不要伪造占位提案
interface ApplyResult {
  ok: boolean; mode: "atomic" | "partial"; seq: number;
  applied: Proposal[]; rejected: Rejected[]; events: Envelope[];
  /** E_SEQ_GAP：expectedSeq 与当前 seq 不符（重放后重试）；E_STORE_FAULT：落盘失败（状态未变，可直接重试） */
  error?: { code: ErrorCode; message: string };
}

// 附：Store 的落盘契约（内存提交 ≠ 可靠存档）
interface Store {
  snapshot(roomId): Promise<WorldState>;
  events(roomId, fromSeq, limit?): Promise<Envelope[]>;
  replay(roomId, toSeq?): Promise<WorldState>;
  /** 等已追加事件真正落盘；Turn 必须在 turn.commit 之前 await，失败则 E_STORE_FAULT */
  flush(roomId: string): Promise<void>;
}

// 附：引擎内部的 EventLog（**只给 Arbiter/Turn**，模块与前端看不到）
interface EventLog extends Store {
  /** 先载入持久层再返回 seq —— 校验 expectedSeq 前必须用它（重启后懒加载会给 0） */
  load(roomId: string): Promise<number>;
  seq(roomId: string): number;      // 内存视图，未 load 前不可信
  state(roomId: string): WorldState;
  /** 文件实现是 async：**写盘成功后才改内存**，失败则内存与 seq 都不变 */
  append(roomId: string, envs: Envelope[]): void | Promise<void>;
}
```

### 2.4 回合引擎 `Turn`

```ts
interface Turn {
  /** 玩家一次输入 → 一次完整回合（含模块、LLM、裁决、记忆） */
  run(req: TurnRequest): AsyncIterable<TurnEvent>;   // 流式，SSE 直接透传
}

interface TurnRequest {
  roomId: string;
  actorId: string;                  // 谁在行动（联机时可能是 NPC）
  input: string;                    // 自然语言原文
  clientTurnId: string;             // 客户端幂等 id，重复提交返回同一回合
  userId?: string;                  // 3.1.0：账号维度；单人从房间成员取，联机由 route 按登录态注入
  targetNpcId?: string;             // 这次行动在跟哪个 NPC 说话（点 NPC 对话时给）；可选参数、旧行为不变，CONTRACT 版本由 Lead 统一落版；用于提示词实名化与"问名字后解锁谁"
  options?: { debug?: boolean; skipLLM?: boolean; budget?: number; expectedSeq?: number };  // expectedSeq 不符 → turn.rejected(E_SEQ_GAP)
}

type TurnEvent =
  | { type: "turn.accepted"; turnId: string }
  | { type: "turn.delta"; field: "narrative" | "dialogue"; text: string }
  | { type: "turn.facts"; facts: string[] }             // 模块给出的既成事实
  | { type: "turn.tool"; name: string; args: unknown; result: unknown }
  | { type: "turn.patch"; ops: Proposal[]; state: WorldState }  // 裁决后的增量
  | { type: "turn.ui"; view: ViewPatch }
  | { type: "turn.commit"; turnId: string; seq: number; usage?: Usage }
  | { type: "turn.rejected"; code: ErrorCode; message: string; retryable: boolean }  // 开工前就被拒（如 expectedSeq 过期），没有 accepted
  | { type: "turn.error"; code: ErrorCode; message: string; retryable: boolean };

// 事件顺序是契约的一部分（客户端可以据此判断"能不能把叙事当真"）：
// accepted → [delta] → [facts] → [ui] → patch → commit
// 裁决失败：accepted → error（没有 delta / patch / commit）
```

**提案阶段顺序（整回合；与实现对齐）**

| # | 阶段 | 谁产出 | 实现位置 | 备注 |
|---|---|---|---|---|
| 1 | 玩家规则 | 现实锚定（`reality.json`）与审核闸门对输入的判定 | `turn.ts` → `reality.ts` / `audit.gate.ts` | 只过滤输入与模型产出，**不单独成批提案** |
| 2 | 模块 intent/tool | 模块 `intent()` / `tool()`（按 manifest priority 升序，第一个返回 ok 的胜出） | `modules.ts` `dispatchIntent` / `callTool` | 只读本回合开始时的快照 |
| 3 | NPC/导演 | LLM 叙事 + 提案（被拒时带原因修复一次；JSON 解析失败时带解析错误重问一次） | `turn.llm.ts` | 提案与模块提案同批裁决 |
| 4 | 记忆 | 六道闸门后的 `memory.write` 提案 | `turn.memory.ts` / `memory.gate.ts` | 与阶段 2/3 同批 `arbiter.apply` |
| 5 | tick | `capabilities.triggers` 命中的到点行为 | `apps/server/src/map.ts` `tick()` | **不在 `Turn` 内**：由 server tick 循环单独 `apply` |

两条实现约束（与上表配套）：

- 阶段 2→3→4 的提案在**同一个 atomic 批**提交，批内顺序固定为 模块 → 模型 → 记忆；阶段 1 不是独立批次，而是对输入/模型产出的过滤（reality 丢弃越界提案、审核闸门可整回合阻断并改走处置）。
- 这一批共享**同一个整回合预算**（`TurnBudget`，见 §2.3）：三次 `apply`（主批 / 去掉记忆重提 / 修复重提）传同一个预算对象，`xWritesPerTurn` 与 `maxDeltaPerTurn` 按回合累计，被拒的批回滚不消耗额度。tick 用独立的 `cause`，与玩家回合互不占用额度；其 `time.advance` 与模块提案目前是两次独立 `apply`（各自归集，不做跨 tick 累计）。

**LLM 输出不合法 JSON 时的两条路（issue #18 / #21-3，3.2.0 起明确）**

- **容错解析**（`turn.parse.ts`）：先按**原文**取第一个平衡的 `{...}`（字符串/转义感知），失败才剥**首尾**围栏重试（不碰中间内容，叙事字符串里含 ``` 的合法 JSON 不被截断）；容忍尾随逗号与前后说明文字；顶层必须是对象。网关 `json:true` 已经容忍围栏/尾随逗号的场景，引擎侧必须同样接受，不能出现"网关认为合法、引擎判死"。
- **自动修复一次**（`turn.llm.ts`）：容错后仍解析不出（截断/缺逗号/空内容），或网关 `json:true` 直接抛 `E_LLM_FORMAT`，引擎带**解析错误摘要**重问一次；第二次仍是坏 JSON 才发 `E_LLM_FORMAT` 的 `turn.error`（`retryable=true`）。若这次重问本身遇到 `E_LLM_TIMEOUT` / `E_RATE_LIMITED`，**保留原错误码上抛**，不误报为格式错（否则超时切 provider、按码分流都会失效）。
- **可重试标记**：`turn.error.retryable` 对 §7 的 `RETRYABLE`（`E_LLM_FORMAT` / `E_LLM_TIMEOUT` / `E_RATE_LIMITED`）与 `E_STORE_FAULT`（写盘失败、本回合未 commit，重试安全）为 `true`；`E_MODULE_FAULT` 等硬失败为 `false`。前端据此决定是否显示重试按钮（web 侧按钮属另一任务）。
- 语义校验失败（提案缺字段/类型错/被 Arbiter 拒）**不混入**这条路径：仍走上面的"带拒绝原因修复一次"，`retryable=false`。

> `TurnEvent` 的 `type` 就是 SSE 的 `event:` 字段，一字不改。

### 2.6 记忆 `Memory`

> 3.1.0 起 `Memory` 是**事件日志的索引投影**（`memory.written` / `memory.tombstoned` → `MemoryRecord`），
> 不是独立真相源：服务重启后由 `rebuild(roomId, store.events(roomId, 0))` 重建。
> 正式写路径唯一：`Proposal → Arbiter.apply → 事件 → ingest`；`write()` 只保留给测试。

```ts
type MemoryTier = "short" | "long" | "permanent";
type MemoryStatus = "current" | "historical" | "tombstoned";

interface Memory {
  /** 按打分召回；secret 走强制通道（forced 不占预算） */
  recall(q: MemoryQuery): Promise<MemoryHit[]>;
  /** 纯派生：不创建实体、不产事件；无记录返回 null（空档案 ≡ 无记录，不违反 I1） */
  profile(userId: string, ownerId: string, roomId: string): Promise<MemoryProfile | null>;
  compact(roomId: string, ownerId: string): Promise<{ impressions: number; archived: number }>;
  /** 测试用，不参与正式写路径 */
  write(roomId: string, drafts: MemoryDraft[]): Promise<void>;
}

interface MemoryQuery {
  roomId: string;             // scope="world" 时传 room_world_<worldId>
  userId?: string;            // 给了就按账号过滤（私忆隔离：A 的 private 记忆 B 查不到）
  ownerId: string;            // 谁的视角（决定能看到什么）
  tiers?: MemoryTier[];       // 缺省 = 全部
  scope?: "room" | "world";
  worldId?: string;
  about?: string[];
  tags?: string[];
  budgetTokens: number;
  nowTurn: number;
}

interface MemoryProfile {
  userId: string;
  roomId: string;
  ownerId: string;
  firstMetTurn?: number;
  familiarity: number;        // 0~1 派生
  impressionIds: string[];    // 该 owner 记住的 permanent 条目
  impressions: number;        // 账号级世界印象计数（跨房间）
  lastTopics: string[];
  seenImpressionIds: string[];
}

interface ImpressionNotice {
  id: string;
  memoryId: string;
  userId: string;
  worldId: string;
  subjectText: string;        // ≤40 字，去掉私密细节
  npcId?: string;
  createdAt: number;
  deliveredAt?: number;
}
```

`MemoryRecord` 在 §10.1 的类型补全表里给完整字段（记忆段：`tier`/`status`/`worldId`/`userId`/`sourceRefs`/`contentHash`/`aboutUserIds`）。

**回合里的记忆链路（P1 实现，行为契约）**

1. **读**：`Turn` 先 `store.events(roomId, 0)` 增量喂给 `Memory.sync`（重启后也成立），再按 `ownerId` 召回三层：
   S1.5 世界层永久记忆（`scope:"world"`、`ownerId:"mem_world"`、≤200 tok）→ S7 长期（≤700）→ S8 短期（≤200），
   三段合计硬顶 **1100 tok**；块内按 `memoryId` 排序，保证提示词逐字节稳定（KV 缓存）。
   `ownerId` = 场景里唯一的 NPC；没有明确对谈对象时是玩家自己。
2. **写**：模型输出的 `memory[]` 先过 `LlmMemoryDraftSchema`（无 `ownerId`，`tier` 只允许 `short|long`），
   再过六道闸门（归属/形状/去重/重要度下限/秘密/配额），最后变成 `memory.write` Proposal。
3. **裁决**：记忆提案与模块/模型提案同批 `apply`；若**只有**记忆提案被拒，整批重提一次（去掉记忆），
   回合照常提交并在 `facts` 里加一条「记忆写入被拒」。记忆写坏不许毁掉玩家的合法行动。
4. **落库后**：`applied.events` 逐条 `Memory.ingest` —— 读路径与写路径共用同一份事件日志，回放必然一致。
5. **读失败**（记忆服务异常）：本回合按"第一次见面"继续，`facts` 加「记忆暂不可用」，绝不向玩家抛错。

世界层 `permanent` 只能由 `canonize` 发起、`ownerId` 固定 `mem_world`、房间固定 `room_world_<worldId>`、
必须 `public` + 带 `contentHash` + `sourceRefs`；同 hash 重复写幂等，内容不同 → `E_MEMORY_IMMUTABLE`。

### 2.7 对话导演 `Dialogue` —— NPC 自主多 agent 对话的唯一入口

> **密谋、闲聊、课堂讨论、玩家插入对话，全部是 `DialogueDirector` 的不同实现**。引擎只提供会话骨架（谁在场、谁能知道什么、发言顺序、写谁的记忆），不关心剧情是"密谋"还是"八卦"。

> **持久化三条纪律**（Issue #1 复审后固化，`packages/engine/src/store.ts` 实现）：
> 1. **写盘先行**：`append` 成功落盘后才改内存。失败 → 内存/seq 不变 → `ApplyResult.error = E_STORE_FAULT`，`Turn` 不发 commit，客户端重试安全。
> 2. **读前先载入**：`expectedSeq` 校验必须用 `load()` 返回的 seq；直接用懒加载前的 `seq()` 会在重启后首回合假报 `E_SEQ_GAP`。
> 3. **坏档可修**：载入时遇到 seq 断档/重复，保留连续前缀并把修复结果写回，房间仍可进（丢的是断档之后的尾部事件）。
> 4. **可选能力**：`FileStore`/`EventSourcedStore` 另实现 `listRooms(): Promise<string[]>`（契约外可选能力：用于房间入口存在性守卫与重启重建；内存测试替身可缺省，缺省时 server 退化为读一页事件探针）。

## 5. 协议层（HTTP / SSE / WS）

### 5.1 原则

- 所有响应体统一 `{ ok: boolean, data?, error?: { code, message } }`。
- 所有流式用 `Envelope`，`event:` 即 `type`，`data:` 即 JSON 序列化的 `Envelope`。
- **无状态请求 + seq 续传**：断线重连带 `Last-Event-ID`（= seq），服务器补发缺失事件。这条是联机的地基。

**路径参数 `roomId`（安全边界）**：所有 `/api/v1/rooms/:roomId/...` 的 `roomId` 必须匹配 `^[A-Za-z0-9_-]{1,80}$`；不匹配一律 `400 E_SCHEMA_INVALID`（不是 404）。原因：`roomId` 会作为 `data/rooms/<roomId>.jsonl` 的文件名，禁止 `/`、`\`、`.` 等路径字符，避免 URL 解码后的 `..%2F..%2F` 穿越数据目录。HTTP 层 `preHandler` 与 `FileStore` 内部各校验一次。非法路径参数不属于既有契约，新增拒绝不 bump `CONTRACT_VERSION`。

#### 5.2.2 模型接入端点（玩家自备 key）

给"玩家在界面里填自己的 API Key"用的最小实现（`apps/server/src/settings.ts` + `apps/server/src/llm-switch.ts`）。key 不进日志、不回显（错误信息中的 key 一并脱敏）；提交时先探活一次（1 个 token 的 ping），失败不切换。接入成功后保存到 `data/llm-settings.json`（`/data/` 在 .gitignore 中，明文、`mode 0o600` 仅属主可读写；删除文件 = 忘记），**重启后自动恢复**；环境变量 `GALGAME_LLM_*` 优先于保存的配置。未接入时叙事由离线叙述器（`apps/server/src/offline-narrator.ts`）生成。

**安全边界（3.5.0 收紧，PR #19 审阅 P1-1）**：配置了用户系统（`auth` 存在）时，这三个端点要求**有效 `x-admin-token`（与 `GALGAME_ADMIN_TOKEN` 同源）或 `role=admin` 会话**，否则 `E_FORBIDDEN`。原"本机 IP"口径（`127.0.0.1`/`::1`）**在反向代理后不成立**——代理后 `req.ip` 恒为 loopback，带会话的任意客户端都能读到全局模型配置，故不再作为唯一凭据；仅未配置用户系统的纯单机开发态保留本机 IP 限制。它们会改服务端出站目标（SSRF 面）且涉及明文 key，**切勿把 8787 端口直接暴露到公网/局域网**。`DELETE` 会把 `baseUrl/model` 一并清空（view 回到全空离线态）。普通玩家界面不展示模型配置入口（收敛稿阶段 A）。

#### 5.2.4 注册表端点（UI 按数据渲染，落实 I2）

前端不得硬编码属性键（issue #3 的收口）：面板/图鉴需要知道"世界里有哪些属性、标签是什么、可见性如何、范围多大"，统一从这里取。**只返回声明，不含任何实体数值**；键与标签都来自 `content/registry/attrs.json`。

| 方法 | 路径 | 入参 | 成功返回 |
|---|---|---|---|
| `GET` | `/api/v1/registry` | — | `{ok:true, attrs:[{key, type, scope, min?, max?, visibility, label, unit?, hidden}]}` |

`visibility` 语义（消费方必须遵守）：`public` 可展示精确值；`self` 只对本人可见（对他人展示需玩法写入后才有值）；`secret` **只展示分档**（如低/中/高），不得下发精确数值。`hidden: true` 的属性（如坐标）不参与面板渲染。

#### 5.2.5 图鉴端点（服务端 GalleryView，落实 I2）

图鉴不再由前端直读 `state.entities[].attrs`：服务端按 `content/registry/attrs.json` 的声明（`label`/`unit`/`min`/`max`/`visibility`/`display.hidden`）把实体属性翻译成**读数**，前端只渲染读数。这样改名/删除属性键只会让该读数消失或按新声明出现，不会在 UI 里静默崩。

| 方法 | 路径 | 入参 | 成功返回 |
|---|---|---|---|
| `GET` | `/api/v1/rooms/:roomId/gallery` | — | `{ok:true, gallery:GalleryView}` |

```ts
interface GalleryView {
  roomId: string;
  player: { actorId: string; locId: string };
  npcs: GalleryNpc[];               // 只含本房间 active 的 npc 实体，按 id 升序
  counts: { met: number; total: number; locs: number };
}
interface GalleryNpc {
  id: string; name: string;          // 未认识时固定为「一位陌生的同学」（不下发真名）
  met: boolean;                     // 一级认识口径：knows_name 为 true（docs/06 §7）；同处一地不算认识
  present: boolean;                 // 在 scene.presentIds 里
  locName?: string;                 // 只在 met 时给
  role?: string; traits?: string[]; line?: string;  // 来自 §5.2.6 的 NPC 档案，只在 met 时给
  mutter?: string;                  // 头顶气泡台词，同样只在 met 时给（地图气泡从本端点取）
  stats: GalleryStat[];             // 未认识时恒为空数组
}
interface GalleryStat {
  key: string; label: string; type: "number" | "string" | "boolean";
  visibility: "public" | "self" | "secret";
  unit?: string;
  display: "exact" | "band" | "text" | "masked";
  value?: number;                    // 仅 display="exact"：public 数值的精确值
  ratio?: number;                    // 仅 display="exact" 且数值属性，0~1（进度条）
  band?: "低" | "中" | "高";        // 仅 display="band"
  text?: string;                     // 仅 display="text"
}
```

`visibility` 口径（服务端统一计算，前端不再重复判定；与 §5.2.4 的声明语义一致）：
- `public`：数值 → `display:"exact"`，给 `value` + `ratio`；文本/布尔 → `display:"text"`，给 `text`；
- `secret`：只给 `display:"band"` + `band`，**响应里不得出现 `value`/`ratio`**。分档按声明的 `min`/`max` 三等分：`t = (value - min) / (max - min)`，`t ≤ 1/3` 低、`t ≤ 2/3` 中、其余高；缺 `min`/`max` 时该属性降级为 `display:"masked"`（`self` 数值同规则）；
- `self`：对**他人**（本端点即玩家看 NPC）不返回精确值——数值降级为 `display:"band"`，文本/布尔降级为 `display:"masked"`（前端显示「—」）。本版本不提供"看自己"的图鉴视图；将来若提供，player 自身的 `self` 读数可返回精确值；
- `display.hidden: true` 的属性与未在注册表声明的属性：**不出现**；未设置值的属性：`display:"masked"`。

`met=false` 的 NPC：`stats` 为空数组，且不带 `locName`/`role`/`traits`/`line`/`mutter`（未遇见不泄露档案、气泡台词与读数）。房间存在性由 `FileStore.listRooms()` 预检——`snapshot` 对不存在的房间返回空 WorldState 而不抛错，不预检就会得到 200+空图鉴；world room（`room_world_*`）先判前缀。错误：房间不存在，或 `roomId` 是 world room → **HTTP 404** `{ok:false, message:"房间不存在"}`；本小节不新增错误码（沿用既有实现中"房间不存在"的实现码）。

> **本端点是图鉴"读数视图"，不是 `/state` 的替代**：`/state` 仍返回原始 `attrs`（含 `self`/`secret` 的精确值），其数值过滤归 issue #3 后续处理；前端渲染图鉴只能用 `GalleryView`，不得用 `/state` 补读数。

|---|---|---|---|

- 只读端点，不写状态、不产事件；目录为空时返回 `{ok:true, openings:[], npcs:[]}`，前端显示「无预设开局」并允许直接开局。

#### 5.2.7 存档与会话恢复端点（issue #7 MVP）

> 只补充条目，不 bump `CONTRACT_VERSION`（与 §5.2 补遗同例）。方案与数据格式见 `docs/09-存档与会话恢复方案.md`；这些端点只读投影（回合历史 / 存档索引）或删索引，不写世界状态。

| 方法 | 路径 | 入参 | 成功返回 |
|---|---|---|---|
| `GET` | `/api/v1/rooms/:roomId/history` | 查询 `fromTurn?`（turnId 或 committedSeq 数字，向前游标）、`before?`（服务端返回的 `earlierCursor`，或旧客户端使用的 committedSeq 数字）、`limit?`（默认 50，上限 200）；同时提供 `turnId` 和 `actorId` 时精确查询单条回合 | `{ok:true, roomId, history: TurnHistoryLine[], lastCommittedSeq, hasEarlier, earlierCursor?}`（按 committedSeq 升序；本房成员可读） |
| `GET` | `/api/v1/me/saves` | 头 `X-User-Id`（账号口径同 §5.2.3） | `{ok:true, userId, saves: SaveEntry[]}`（按 updatedAt 降序） |
| `DELETE` | `/api/v1/me/saves/:roomId` | 头 `X-User-Id` | `{ok:true, roomId, removed:boolean}`；只删索引，不删房间与历史 |

`POST /api/v1/rooms` 的请求体在 §5.2.3 基础上新增可选 `scenarioId`（截断 64），用于建房时登记存档索引。

**分页口径（3.5.0 起）**：不带游标时返回最近 `limit` 条。`hasEarlier=true` 时服务端返回当前页首条记录的 `earlierCursor`。下一页把该值作为 `before` 原样传回，获取该记录之前最近 `limit` 条；同一提交序号的记录按写入顺序分页，游标所属条目不包含在下一页。未知的记录游标返回空页。旧的 `before=<seq>` 仍只返回序号严格小于该值的记录，`fromTurn` 向前翻页口径不变。`TurnHistoryLine` 增可选 `clientTurnId?`（**仅落盘**，用于额度对账与重试核对，不下发；旧行缺省不影响读取）。历史去重与引擎幂等作用域一致：房间内按 `actorId + turnId`（`turnId` 已含 `clientTurnId`），同房间不同角色使用同一回合 ID 时两条历史都保留。

精确查询按房间内的 `turnId + actorId` 匹配，优先于分页游标；少传其中一个或传空值返回 400 `E_SCHEMA_INVALID`，没有匹配则返回空的 `history`。多个回合可共享同一个 `committedSeq`。精确查询的响应保留调用方提供的标识，历史文案仍按当前认识状态脱敏。

历史追加同样在每条记录前先写换行，半截尾行不会吞掉下一条历史。历史文件独立放在 `data/history/<roomId>.jsonl`（`data/rooms/` 只放事件日志，避免被 `FileStore.listRooms()` 当作幻影房间）。缺少历史文件时视为空历史，其它文件读取故障由历史和行动核对端点返回 503 `E_STORE_FAULT`。`GET .../history` 响应不含 `userId`（仅落盘用于归属/审计）；成员校验与其它房间端点同一 gate（§5.2.8 房间授权）：3.1 之前建房、成员表没有 `userId` 的老房间，`authRequired=0` 时知道 `roomId` 者可只读历史，`authRequired=1` 时默认 403（管理员令牌例外）。

```ts
interface TurnHistoryLine {
  formatVersion: 1;
  roomId: string; turnId: string; committedSeq: number;
  actorId: string; userId?: string;   // 仅落盘，不下发
  clientTurnId?: string;              // 仅落盘，不下发；额度对账/重试核对
  input: string; narrative: string;
  speakers: string[];   // 3.1.0 事件流无逐句 speaker，固定 []
  facts: string[];
  createdAt: number;
}
interface SaveEntry {
  roomId: string; scenarioId: string;
  createdAt: number; updatedAt: number;
  lastTurnId: string; lastCommittedSeq: number;
  actorId?: string;                  // 建房签发的房间内角色 id；3.3 前的老存档缺省，恢复时按成员表兜底
  formatVersion: 1;
}
```

错误语义：未带账号 → 400 `E_SCHEMA_INVALID`；房间不存在/世界层房间 → 404 `E_ROOM_NOT_FOUND`（§10.17，与 `/state` 一致）；非本房成员读历史 → 403 `E_FORBIDDEN`。

#### 5.2.8 用户系统（3.5.0，邀请注册 + 会话）

> 简易账号系统：用户名/密码登录，身份只来自 HttpOnly Cookie `ecust_sid`；不再使用 localStorage `ecust.playerId`、`X-User-Id` 或 body `userId` 作为身份来源。部署时置 `GALGAME_AUTH_REQUIRED=1` 后，除公开端点外都要求会话。

| `POST` | `/api/v1/auth/login` | `{username, password}` | 同上 |

- 用户名：小写 `[a-z0-9_-]{3,24}`；密码 8–128 位；服务端用 `scrypt` 哈希，不存明文。
- **邀请注册（3.5.0，收敛稿 B1）**：注册消耗管理员签发的有限邀请码（摘要存储、创建时展示一次、可设次数/有效期/撤销，见 §5.2.9）；「账号创建 + 邀请扣减」在同一串行写内原子完成，并发最后一次只一人成功，写盘失败不消耗邀请；**是否开放以事务内最新的 `doc.settings.registrationOpen` 为准**（密码哈希期间管理员关闭注册，在途请求也不会建号）。`GALGAME_INVITE_CODE` 保留为**开发兼容共享码**（不限次数，生产应改用一次性邀请）；两者皆无或 `registrationOpen=false` → 403 `E_FORBIDDEN`（注册关闭）。重复用户名 → 409 `E_ID_TAKEN`，**不返回已有账号的会话**；响应丢失后走正常登录恢复（唯一约束防重复，非完整幂等重放）。
- **角色与状态（3.5.0）**：`role: player|admin`（注册一律 player，管理员只能由本地初始化脚本或现有管理员授予）；`state: active|suspended|archived`（独立于角色）。`suspended/archived` 禁止登录与新行动，**每次受保护请求校验当前账号状态**（不只信登录时快照），暂停即撤销该账号全部会话；存档保留。
- **登录失败**统一 `401 E_UNAUTHORIZED`，不区分用户名是否存在；限流见下。登录/注册/重置/邀请尝试分别限速（账号渐进延迟 + 全局上限 + 邀请尝试限制 + IP 粗筛组合；`GALGAME_TRUST_PROXY=1` 时按真实 IP 计数）；超限 → 429 `E_RATE_LIMITED`。
- **CSRF（3.5.0，复审收紧）**：同源部署 + `SameSite=Lax`；`authRequired=1` 时，**全部写请求**（POST/PUT/PATCH/DELETE）必须带 `Origin` 且命中 `GALGAME_PUBLIC_ORIGIN` 允许值，缺失/不符 → 403 `E_FORBIDDEN`。`/api/v1/auth/*` 的写路由（`register/login/logout/password/reset-password`）**不再豁免**——否则攻击者可跨站把受害者登进攻击者账号（login CSRF）；无会话的非 auth 写请求（登录前首次建房等）豁免；`x-admin-token` 认证的运维调用豁免；不信任 `Host`/转发头。`authRequired=0` 开发态不校验。
- Cookie：`HttpOnly; SameSite=Lax; Path=/; Max-Age=7d`；HTTPS 部署加 `Secure`。前端不读取 Cookie，也不保存 token。
- 公开端点（`GALGAME_AUTH_REQUIRED=1` 时）：`GET /api/v1/health`、`GET /api/v1/registry`、`GET /api/v1/scenarios`、`/api/v1/auth/*`。其余（房间/回合/存档/历史/地图/图鉴/审核）都要求会话。
- 兼容：`GALGAME_AUTH_REQUIRED=0`（默认）保留原有 header/body `userId` 兜底，供本地测试；生产必须置 1。
- **房间授权（issue #33）**：登录只解决身份；所有房间读写入口（`state`/`events`/`turns`/`map`/`map/travel`/`map/tick`/`map/dialogue`/`gallery`/`history`）统一校验成员资格——房间成员表存在任一 `userId` 时，当前用户必须在其中，否则 `403 E_FORBIDDEN`。写操作（`turns`/`travel`/`dialogue`）额外要求 `actorId` 是当前账号在本房间的 `role=player` 角色；`body.userId`/`X-User-Id` 不能覆盖会话身份。例外策略：① 旧档（成员表无 `userId`）在 `authRequired=1` 时默认不开放（403），`authRequired=0` 保持旧开放度；② 有效 `x-admin-token` 可越过成员/角色绑定（运维恢复通道；token-only 无会话也可访问房间端点，且同样计失败限流）；③ 世界层房间仍一律 404。授权通过不意味着可见秘密原始字段（`/state` 视角裁切仍是 issue #3 余项）。**存储故障不折叠为 404（复审 P1）**：房间已由存在性守卫证实存在后，`snapshot` 读取失败（存档损坏/IO 故障）→ 503 `E_STORE_FAULT`，不得返回 `E_ROOM_NOT_FOUND`（否则客户端会误清房间指针，且掩盖存储故障）。未预期 fs/持久化异常统一 503 `E_STORE_FAULT` 且不回显路径（全局 error handler）；其余未预期异常 500 `E_MODULE_FAULT`。

#### 5.2.9 管理端点（3.5.0，收敛稿 B1）

> 鉴权：有效 `x-admin-token`（运维兼容，**不得发给体验者**）或 `role=admin` 会话；二者皆无 → 401/403。**令牌校验（复审 P1）**：比较一律 sha256 摘要 + `timingSafeEqual`（常量时间，禁止 `===`）；显式配置的 `GALGAME_ADMIN_TOKEN` 至少 16 字符且估算熵 ≥ 96 bit，否则**拒绝启动**（未配置时每进程随机生成）；同一 IP 的令牌失败（仅当请求确实带令牌时计数）10 次/60s 后 → 429 `E_RATE_LIMITED` + `Retry-After`，窗口内正确令牌也拒绝，成功一次清零；同一请求经过登录门/CSRF/room-guard/管理路由时共用请求级判定缓存，**只计一次失败**。所有写操作记入操作日志（操作者/目标/时间/原因/结果，**不记密码/token/聊天内容**）。首版以端点 + 服务端脚本交付（B1），完整管理页面（B2）后置。未知 userId/邀请 id → 404 `E_REF_NOT_FOUND`。

#### 5.2.10 额度与行动核对（3.5.0，收敛稿 B1）

> 额度按**逻辑请求**（`clientTurnId`）结算，状态机：`已预留 reserved → 执行中 running → 已提交 committed / 已确认失败 failed / 结果待核对 unconfirmed`。成功回合按一个逻辑请求扣一次；失败重试不重复扣。预留过期**不自动释放**，触发核对（与历史提交事实对账）；`unconfirmed` 需管理员 resolve 或核对到提交事实后才结案；管理员 resolve 先落盘再确认，写盘失败 → 503 `E_STORE_FAULT` 且保持 `unconfirmed` 可重试；同一账本的状态检查、落盘、内存更新整体串行，并发结案仅首个成功，其余 409 `E_ILLEGAL_OP`，历史自动对账与人工结案共用同一状态规则；自动对账写盘失败 → 503 `E_STORE_FAULT`，不伪装成 `200 unconfirmed`。`#34`（引擎提交事实持久化）未交付前，断线窗口的最终核对依赖管理员（残留风险，收敛稿明示）。

- **幂等键作用域（PR #19 复审 P1-1）**：逻辑请求以 `userId + roomId + clientTurnId` 三元组定位，不同账号/房间的同名 ID 互不影响；`actorId` 随条目落库，同一三元组复用 ID 但换了角色 → 409 `E_PRECONDITION`（避免同房间两角色混用同一逻辑 ID）。
- **重启恢复（PR #19 复审 P1-2）**：进程启动时重建账本，遗留 `running`（已开跑、结果未知）→ `unconfirmed`；遗留 `reserved`（尚未开跑）→ `failed` 并释放额度。否则重启后账号会被永久 `E_TURN_BUSY` / 白占额度。为保证该前提成立，`running` 必须**确认落盘后**才开始执行：写盘失败 → 503 `E_STORE_FAULT`（未开跑、可重试），内存条目置 `failed` 释放额度。
- 每日额度：`settings.defaultDailyTurns`（null=不限）+ `perUserDailyTurns[userId]` 覆盖；**个人键存在即视为显式设置**（显式 `null`=不限，不回退全局默认），回合入口与管理列表共用同一解析口径。按**占用态**（`reserved`/`running`/`committed`/`unconfirmed`，`failed` 释放）在自然日计数。达限 → 429 `E_RATE_LIMITED`（「本轮体验额度已用完」）。
- 全局开关：`settings.actionsEnabled=false` 时新行动 → 429 `E_RATE_LIMITED`（「本轮体验已暂停新行动」）；**不阻止**登录、读存档/历史。地图 `travel`/`tick`/`dialogue` 这类写入口与回合入口共用同一暂停检查，暂停期间不推进时段、不写回合历史。
- 每用户并发行动上限 1（`running` 占用）→ 409 `E_TURN_BUSY`。
- 重复 `clientTurnId`：已 `committed` → 409 `E_PRECONDITION`（附 `committedSeq`，客户端据此刷新而非重跑）；`running/unconfirmed` → 409 `E_TURN_BUSY`/`E_PRECONDITION`，先核对。**`unconfirmed` 不得复用原 ID 重发**；客户端先核对状态，失败方可换新 ID。
- 行动核对（本房成员可读）：`GET /api/v1/rooms/:roomId/turns/:clientTurnId` → `{ok:true, state, turnId?, committedSeq?}`；不存在 → 404 `E_REF_NOT_FOUND`。与历史对账时按 `userId + actorId + clientTurnId` 三元组匹配提交事实（同房间不同账号可能复用同一 ID，只比 ID 会认错回合；缺 `userId` 的旧历史行不参与自动对账）。人工结案为 `committed` 但缺少 `turnId` 时，核对响应可从同一作用域的匹配历史补齐回合标识。客户端用响应的 `turnId` 和本次行动的 `actorId` 精确查询历史，补齐断流期间未收到的叙事/facts。
- 账本落盘 `data/auth/ledger.jsonl`（append-only 投影，重启重建；与历史一样可丢可重建，不是权威状态）；操作日志 `data/auth/admin-actions.jsonl`。**每条追加后 `fsync`（复审 P1）**：`transitionDurable` 返回即代表记录已落盘，崩溃/断电不会丢掉"已承诺写入"的最后一条。**加载时不可解析的行（崩溃留下的半截尾行/结构不符）跳过并计数**，`console.warn` 告警且经 `GET /admin/quota` 的 `skippedLines` 暴露给运维；被跳过条目不再参与幂等/对账，需人工确认。**每次追加都先写换行分隔**，即使上次写入只落了半截尾行（短写/崩溃/外部损坏），新记录也从行首开始，避免粘成新的坏行（复审 P1）。**读取失败（非 ENOENT）拒绝启动**（`LedgerUnreadableError`）：否则会把读不出的账本当新账本，丢失已提交记录并重新接受已用过的逻辑 ID；仅"文件不存在"按空账本启动。

> **下发前脱敏（认识口径）**：`POST /turns` 的 SSE 事件、`GET /events` 与 `GET /rooms/:roomId/state` / `GET .../history`，在写出前都会把**尚未认识**的 NPC 真名替换成外貌占位名（`content/scenarios/npcs.json` 的 `appearance`，缺省退回「第N位陌生的同学」）——模型会把名字写进叙事/台词（`严守一：…`）与 `turn.facts`（`【世界印象】严守一记住了你`），不脱敏等于把名字直接告诉玩家。
>
> **判定时点**：用**本回合结束后的状态**（收齐事件后按最终 `turn.patch.state` 算一次映射再统一写出）。玩家问「你叫什么」、NPC 回答「我叫林静」的那一回合，林静已经算认识，名字必须原样出现，否则会出现"陌生人自我介绍"的荒谬结果。
>
> **SSE 时序取舍（审阅 P1-6）**：因为脱敏名单依赖回合结束状态，本版本的 `POST /turns` 是"收齐事件 → commit → 一次性写出"，即**事件不再逐条实时下发**（首个 `turn.delta` 会延迟到 commit 前后）。前端有本地打字机，视觉上仍是逐字出现；如果以后要恢复真流式，需要改成"开始时先按旧名单实时发、commit 后补发修正"的两段式方案。
>
> **解锁入口**：`content/modules/introduce` 只写私忆（"这位同学问我名字/自我介绍叫X"），**不置位** `knows_name`；置位由服务端做——有 `targetNpcId` 且玩家问名字时只解锁该目标（要求目标在 `scene.presentIds`），无目标时按台词里是否真的出现姓名判定；两者都只在 `turn.commit` 之后执行。
>
> **旧存档**：3.4 之前建的房间没有 `knows_name` 属性，升级后其中所有 NPC 都会被当成陌生人——需要重新询问名字；这是刻意选择的"不猜历史"，PR 与 CHANGELOG 已注明。
| `npc.spoke` | S→C | NPC 主动发言（玩家不在场也可推送摘要） |
| `plot.ping` | S→C | "夜里似乎有人说话…"氛围提示 |

## 6. LLM 工具名（function calling）

- 格式严格 `<moduleId>.<verb>`，例：`trade.buy`、`study.quiz`、`social.gift`。
- 引擎工具（非模块）用保留命名空间：`core.move`、`core.observe`、`core.wait`、`core.say`、`actor.emote`。
- 每个工具必须有：`description`（≤120 字）、`parameters`（zod → JSON Schema）、`costWeight`。
- 工具返回统一 `{ ok, facts: string[], proposals: Proposal[] }`。
- 注入策略：只注入"当前地点 + 在场者"相关模块的工具，且总数 ≤ 24 个（超了按 manifest `priority` 截断，防止工具表膨胀）。
