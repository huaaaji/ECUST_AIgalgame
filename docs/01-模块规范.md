# 01 · 模块规范（写给写玩法模块的人）

> 你负责搭「学习 / 娱乐 / 交易」这些玩法；引擎（`packages/engine`）由别人维护，**你不许改它**。
> 这份文档保证一件事：**你新增玩法只需要加一个目录 + 数据文件，引擎零改动**。
> 名字以 [03-接口总表](./03-接口总表.md) 为准，数据结构以 [02-数据格式](./02-数据格式.md) 为准；本文只讲「怎么写模块」。

口诀：**Module 算数，Director 说话，Engine 记账。**
模块负责「规则、数值、可选动作」；叙事由导演/LLM 负责；**所有状态变化只能以 Proposal 交给引擎落库**。

```ts
// content/modules/trade/module.ts
import type { ModuleContext, ModuleOutcome, Proposal, Phase, ContextSlice, ViewPatch } from "@galgame/shared";
import { z } from "zod";
import goods from "./data/goods.json" with { type: "json" };

const BuyArgs = z.object({ itemId: z.string(), qty: z.number().int().min(1).max(5) });

export default function createModule() {
  return {
    /** 玩家说「来瓶肥宅快乐水」→ 引擎先分类出 intent=buy，再交给你 */
    async intent(ctx: ModuleContext): Promise<ModuleOutcome> {
      const g = goods.find((x) => x.id === ctx.args?.itemId);
      if (!g || ctx.state.entities[`item_${g.id}`]?.attrs.money === undefined) {
        // 认领失败时返回 ok:false，引擎会继续问下一个模块
        return { ok: false, proposals: [] };
      }
      const player = ctx.state.entities[`plr_${ctx.actorId}`] ?? ctx.state.entities["plr_self"];
      if (Number(player?.attrs.money ?? 0) < g.price) {
        return { ok: true, proposals: [], facts: [`${g.name}要 ${g.price} 元，你钱不够。`] };
      }
      return {
        ok: true,
        proposals: [
          { op: "attr.delta", args: { entityId: player!.id, key: "money", delta: -g.price }, reason: `买 ${g.name}`, by: "mod.trade" },
          { op: "entity.create", args: { entity: { id: `item_${g.id}_${ctx.turn}`, kind: "item", name: g.name, attrs: { price: g.price }, tags: ["消耗品"], origin: "ai", canon: false } }, reason: "购买获得", by: "mod.trade" },
          { op: "link.create", args: { from: player!.id, to: `item_${g.id}_${ctx.turn}`, kind: "holds" }, reason: "持有", by: "mod.trade" }
        ],
        view: { panel: { money: { label: "零钱", value: Number(player?.attrs.money ?? 0) - g.price } } }
      };
    },
    /** LLM function calling 落地：名字必须是 trade.<verb> */
    async tool(ctx: ModuleContext): Promise<ModuleOutcome> { return { ok: true, proposals: [] }; },
    /** 时段切换（clock.advanced / 夜间 tick）——串行执行，别做长 IO */
    async tick(_ctx: ModuleContext, _phase: Phase): Promise<Proposal[]> { return []; },
    /** 本回合要注入 LLM 的上下文（被 token 预算裁剪） */
    context(ctx: ModuleContext): ContextSlice[] {
      const loc = ctx.state.entities[ctx.loc];
      if (!loc || loc.kind !== "loc") return [];
      return [{ kind: "list", priority: 50, text: `小卖部在售：${goods.map((g) => `${g.name} ${g.price}元`).join("、")}` }];
    },
    /** 模块自有视图（商店面板） */
    view(_ctx: ModuleContext): ViewPatch | null {
      return { panel: { shop_count: { label: "在售", value: goods.length } } };
    }
  };
}
```

**注意这个例子里没有任何** `import { db }` / `import OpenAI` / `applyState()` / `if (moduleId === "trade")`。模块只做三件事：读 `ctx`（只读）、算、返回 `Proposal[]`。

## 2. 目录与硬性禁令

| 允许 | 禁止（违反 review 直接拒） |
|---|---|
| 读 `ctx.state` / `ctx.registry` / 自己的 `data/` | `import` 任何 `packages/engine`、`apps/*` |
| 返回 `Proposal[]` / `ViewPatch` / `ContextSlice` | 直接写库、直接 `fetch` 模型 API、持有 LLM client |
| 用 `ctx.rng()` 取随机数 | `Math.random()`（破坏回放确定性） |
| 用 `ctx.load()` 读数据文件 | 读 `content/canon/**`（走 `ctx.state` 拿投影） |
| 在 `data/` 加 JSON | 在模块里硬编码世界观/剧情文本（那是导演与 canon 的事） |
| 每个文件 ≤300 行 | 单文件 800 行「全能 module.ts」 |

## 3. `manifest.json` 全字段

| 字段 | 类型 | 必填 | 默认 | 语义 / 校验 |
|---|---|---|---|---|
| `id` | string | ✅ | — | `^[a-z][a-z0-9_]*$`，不得占用保留 ns（`core/world/actor/npc/mem/plot/mod/net/view/admin/x`）；目录名必须等于 id |
| `name` | string | ✅ | — | 中文显示名（给 debug 面板） |
| `version` | semver | ✅ | — | 模块自身版本 |
| `apiVersion` | `2` | ✅ | — | 契约版本；引擎不匹配则拒绝加载（`E_MODULE_FAULT` 类） |
| `dependsOn` | string[] | — | `[]` | 依赖的其他模块 id；拓扑加载，缺失则跳过并告警 |
| `capabilities.intents` | string[] | ✅ | — | 接受的意图名（≤16），给程序看：`trade.buy` |
| `capabilities.keywords` | string[] | ❌ | `[]` | 意图路由关键词（≤24），给玩家说话用：`["买","卖","商店"]`。引擎用 **intents 尾段 + keywords** 一起匹配玩家原文——只写英文 intent 名，中文输入永远路由不到模块 |
| `capabilities.tools` | string[] | ✅ | — | LLM 工具名，**必须 `<自身id>.<verb>`**（≤32）；撞名 = 加载失败 |
| `capabilities.triggers` | string[] | ✅ | — | 订阅的事件 type（如 `clock.advanced`）；新事件只改 `events.json`，此字段不锁枚举 |
| `capabilities.views` | string[] | ✅ | — | 提供的视图名（前端路由用） |
| `capabilities.contentFiles` | string[] | — | — | 本模块声明的数据文件（构建期校验存在） |
| `priority` | int 0~1000 | ✅ | — | `dispatchIntent` 按此升序；第一个 `ok:true` 的胜出 |
| `costWeight` | number 0~10 | ✅ | — | 预算分配权重（总 token 按权重切） |
| `budget.maxLlmCallsPerRoomHour` | int | — | `0` | 本模块每小时可发起的 LLM 调用；0 = 纯规则模块 |
| `budget.maxTokensPerTurn` | int | — | `0` | 单回合 token 上限；超了 `E_BUDGET` |
| `limits.proposalsPerTurn` | int | — | `8` | 单回合 Proposal 条数上限；超出截断并记 `E_OVER_LIMIT` |
| `limits.maxArrayItems` | int | — | `16` | 数组 args（presentIds/tags）长度上限 |
| `entryLocations` | string[] | — | `[]` | 只在哪些地点激活；空 = 全地图 |

## 4. 生命周期

```
加载（进程启动）
 1 扫描 content/modules/*/manifest.json
 2 校验 manifest（zod）          失败 → 跳过该模块 + 错误日志（不阻止启动）
 3 解析 dependsOn（拓扑排序）    缺失依赖 → 跳过 + 告警
 4 检查 tools 名冲突             冲突 → 后加载者被跳过（确定性：按 id 字典序）
 5 注册 capabilities（intents/tools/triggers/views）
 6 调 init()（可选，加载自身数据）  抛错 → 该模块标记 unhealthy，路由跳过
运行期
 7 dispatchIntent：intent 匹配 → 按 priority → 第一个 ok 胜出
 8 callTool：LLM 要求调 trade.buy → 定位模块 → tool()
 9 tick：事件触发（clock.advanced 等）→ 串行按 priority
10 context：每回合收集切片，按预算裁剪
故障
11 任一方法抛错 → 捕获 → E_MODULE_FAULT → 本回合跳过该模块继续（**不能 500**）
12 unhealthy 连续 3 次 → 摘除到房间结束（不重启进程）
```

**fail-fast 与隔离的分界**：manifest/契约层面错误 → 该模块不加载；运行期抛错 → 只影响当次调用，不扩散。

### 5.1 上下文类型（此前 03 未定义，以本文为准）

```ts
interface ModuleContext {              // 只读 + 受控能力，模块不能改它
  roomId: string;
  actorId: string;                     // 本次行动者（联机时可能是 NPC）
  turn: number;                        // 游戏回合序号
  phase: Phase;
  loc: string;                         // 当前地点 entityId
  state: Readonly<WorldState>;         // 世界状态快照（深只读）
  registry: Registry;
  intent?: string;                     // dispatchIntent 时：命中的意图名
  args?: Record<string, unknown>;       // 意图参数 / tool 参数（已 zod 校验）
  input?: string;                      // 玩家自然语言原文
  rng: () => number;                   // 确定性随机（种子 = roomId+turn）
  load<T>(file: string): Promise<T>;   // 读自己 data/ 下文件
  budget: { tokensLeft: number };       // 本回合剩余 token（只读）
}

interface ModuleOutcome {
  ok: boolean;                         // 是否“认领”了这次请求；false → 继续问下一个模块
  proposals: Proposal[];               // 状态变化（唯一出口）
  facts?: string[];                    // 既成事实，进叙事但不落库（如“钱不够”）
  view?: ViewPatch | null;             // 可选 UI 增量
  hint?: string;                       // 给 LLM 的一句提示（≤60 字）
}

interface ContextSlice { kind: "state" | "rule" | "list" | "hint"; text: string; priority: number }  // priority 越小越先保留
interface ModuleInfo { id: string; name: string; version: string; apiVersion: 3; capabilities: Capabilities; priority: number; costWeight: number; healthy: boolean }
```

### 5.2 方法契约

| 方法 | 何时调用 | 你必须做 | 你不能做 | 超时 / 预算 | 失败后果 |
|---|---|---|---|---|---|
| `init(ctx?)` | 加载后一次 | 校验 `data/` 自洽 | IO 外呼、改状态 | 5s | 模块 unhealthy |
| `intent(ctx)` | 玩家输入命中 `intents`/`keywords` | 返回 `ok:true` + proposals；或 `ok:false` 让位 | 生成叙事文本（那是导演） | 100ms | `E_MODULE_FAULT`，继续下一模块 |
| `tool(ctx)` | LLM function calling | 同 intent，args 已校验 | 校验 args 之外的事（zod 已做） | 300ms | 工具返回错误给 LLM，回合继续 |
| `tick(ctx, phase)` | 订阅的事件发生 | 返回 proposals 数组（可空） | 长 IO、调 LLM（除非预算允许且 ≤1 次） | 2s | 本夜跳过该模块 |
| `context(ctx, budget)` | 每回合组装 prompt 前 | 返回 ≤budget 的切片 | 返回大段文本（会挤掉记忆） | 20ms | 该模块上下文被丢弃 |
| `view(ctx)` | 前端请求该 view | 返回 `ViewPatch`（增量） | 返回全量 DOM/HTML | 50ms | 视图空 |

> **`view` 返回的是增量 `ViewPatch`**：`{ position?, panel?, choices?, list? }`（见 03 §5.5）。前端只渲染，不做业务判断。

## 6. 产出规则：只能用 13 个原语

| 你想做 | 用哪个 op | args 要点 |
|---|---|---|
| 扣钱/加体力/调好感 | `attr.delta` | `{entityId, key, delta}`；clamp 交引擎 |
| 设置枚举/字符串（心情、等级） | `attr.set` | 值必须过 registry 的 `values` |
| 生成商品/掉落物/临时 NPC | `entity.create` | `origin:"ai"`, `canon:false`，会消耗配额 |
| 改名/加标签 | `entity.update` | canon 实体只能改白名单字段 |
| 让 NPC 退场 | `entity.tombstone` | 先查引用完整性（02 §6.1） |
| 建立「持有/认识/欠人情」 | `link.create` | `kind` ∈ knows/owes/holds/located_in/member_of |
| 解除关系 | `link.remove` | 同上 |
| 玩家/NPC 换地点 | `move.to` | 目标必须邻接 |
| 推进时段 | `time.advance` | 只有引擎/tick 能发，模块用 `tick` 即可 |
| 切换场景与在场者 | `scene.set` | 模块一般不改（导演/引擎负责） |
| 让某人记住一件事 | `memory.write` | `ownerId === ctx.actorId`，否则 `E_FORBIDDEN` |
| 建一条剧情线 | `plot.upsert` | 剧情线是导演的活；模块最多 `status:"stale"` |
| **模块内部记账**（冷却、计数） | ❌ 不是 op | 用 `module_state` 表 + `ctx` 之外的返回值？**不行**——见下 |

**模块自己的状态怎么办？** 模块不许直接写库，但可以通过 **`module_state` 投影**读取（`ctx.state.modules[id]`，只读），写入只能通过……**没有 op**。
因此：模块内部状态必须**表达为世界状态**（如 `x.trade_cooldown_until` 放在玩家实体上），或设计成**无状态纯函数**（优先）。
这是有意的取舍：**任何"模块私有黑盒状态"都会让存档、回放、联机对不上**。

### 6.1 模块不该做的四件事

1. **不 clamp**：`delta:-999` 直接传，引擎按 registry 的 min/max 截断并记 `clamped`。
2. **不判合法性**：钱够不够、地点对不对——引擎统一校验；你判了也只算提示（`facts`）。
3. **不决定可见性**：哪些事件广播给谁由 `events.json` + Transport 决定。
4. **不写文案**：叙事、台词、氛围一律由导演生成；你只能给 `facts` 与 `hint`。

## 7. 完整模板：`library` 借书模块

```json
// content/modules/library/manifest.json
{
  "id": "library", "name": "图书馆借阅", "version": "0.1.0", "apiVersion": 2,
  "capabilities": { "intents": ["borrow", "return_book", "search_book"],
                    "tools": ["library.borrow"], "triggers": ["clock.advanced"], "views": ["books"] },
  "priority": 40, "costWeight": 0,
  "budget": { "maxLlmCallsPerRoomHour": 0, "maxTokensPerTurn": 0 },
  "limits": { "proposalsPerTurn": 6, "maxArrayItems": 8 },
  "entryLocations": ["loc_library"]
}
```

```ts
// content/modules/library/module.ts
import type { ModuleContext, ModuleOutcome, Proposal, ContextSlice, ViewPatch } from "@galgame/shared";
import { z } from "zod";
import books from "./data/books.json" with { type: "json" };

const BorrowArgs = z.object({ bookId: z.string().regex(/^bk_[a-z0-9_]+$/) });

export default function createModule() {
  const findBook = (id: string) => books.find((b) => b.id === id);
  return {
    async intent(ctx: ModuleContext): Promise<ModuleOutcome> {
      const parsed = BorrowArgs.safeParse(ctx.args ?? {});
      if (!parsed.success) return { ok: false, proposals: [] };
      const book = findBook(parsed.data.bookId);
      if (!book) return { ok: true, proposals: [], facts: ["书架上没有这本书。"] };
      if (book.copies <= 0) return { ok: true, proposals: [], facts: [`《${book.title}》已经被借光了。`] };
      return {
        ok: true,
        proposals: [
          { op: "entity.create", args: { entity: { id: `item_${book.id}_loan`, kind: "item", name: `《${book.title}》`,
              attrs: { price: book.price, x.loan_days: 14 }, tags: ["图书", "借阅"], origin: "ai", canon: false } },
            reason: `借出《${book.title}》`, by: "mod.library" },
          { op: "link.create", args: { from: ctx.actorId, to: `item_${book.id}_loan`, kind: "holds" }, reason: "借阅", by: "mod.library" }
        ],
        hint: `你从书架上抽出《${book.title}》。`
      };
    },
    context(ctx: ModuleContext): ContextSlice[] {
      if (ctx.loc !== "loc_library") return [];
      return [{ kind: "list", priority: 40, text: `可借：${books.filter((b) => b.copies > 0).map((b) => b.title).join("、")}` }];
    },
    view(_ctx: ModuleContext): ViewPatch | null {
      return { list: { title: "书架", items: books.filter((b) => b.copies > 0).map((b) => ({ id: b.id, label: b.title })) } };
    }
  };
}
```

## 8. 模块测试（三件必写）

用 `packages/testkit`（提供 `makeCtx(overrides)` 与 `expectProposals`）：

```ts
import { describe, it, expect } from "vitest";
import { makeCtx } from "@galgame/testkit";
import createModule from "../module";

const mod = createModule();

it("正常购买：扣钱 + 生成物品 + 建立持有关系", async () => {
  const ctx = makeCtx({ actorId: "plr_self", args: { itemId: "cola", qty: 1 }, turn: 12 });
  const out = await mod.intent(ctx);
  expect(out.ok).toBe(true);
  expect(out.proposals.map((p) => p.op)).toEqual(["attr.delta", "entity.create", "link.create"]);
  expect(out.proposals[0].args).toMatchObject({ key: "money", delta: -6 });
});

it("钱不够：只给事实，不产生任何 Proposal", async () => {
  const ctx = makeCtx({ actorId: "plr_self", args: { itemId: "cola" }, money: 0 });
  const out = await mod.intent(ctx);
  expect(out.proposals).toHaveLength(0);
  expect(out.facts?.[0]).toContain("钱不够");
});

it("模块抛错被隔离，回合不崩", async () => {
  const ctx = makeCtx({ actorId: "plr_self", args: { itemId: "🍔" } });   // 非法 id 触发 zab 失败路径
  await expect(mod.intent(ctx)).resolves.toMatchObject({ ok: false });
});
```

断言 **Proposal 的 op 与关键 args**，不断言叙事文案（文案会变，契约不会）。

## 9. 禁忌清单 / Code Review Checklist

| 症状 | 原因 | 正确做法 |
|---|---|---|
| 存档回放对不上 | 用了 `Math.random()` / `Date.now()` | 用 `ctx.rng()` / `ctx.turn` |
| 联机时两人看到不同数值 | 模块自己缓存了状态 | 状态一律落世界状态，模块无私有内存 |
| 换个存档就崩 | 读了 `content/canon/**` 文件 | 从 `ctx.state` 读投影 |
| 加个玩法要动引擎 | 直接改了 `WorldState` 或新增 op | 只能用 13 个原语；不够就找引擎维护者讨论 (bump apiVersion) |
| NPC 说的话和数值矛盾 | 模块写了叙事文案 | 只给 `facts`/`hint`，叙事交给导演 |
| 一回合花爆 token | `context()` 返回大段文本 | 切片 ≤200 字、按 priority 排 |
| 深夜 tick 卡死 | `tick()` 里 `await fetch` | tick 只做规则计算，LLM 调用交给导演 |
| 开发板一启动就红 | manifest 字段缺失/工具名撞车 | 跑 `npm run check:contract` |

**提交前 checklist**

- [ ] 目录名 = manifest.id，六方法里实现的方法都有测试
- [ ] `capabilities.tools` 全部 `<id>.<verb>`，无重复
- [ ] 没有任何 `import` 指向 `packages/engine` / `apps/*`
- [ ] 没有 `Math.random` / `Date.now` / `fetch`
- [ ] 所有数值变化走 `attr.delta`，没有手写 clamp
